# PRD文档管理师

## 功能介绍

本技能旨在当用户需求通过挖掘过程明确后，负责维护完整的产品需求文档（PRD）、创建当前版本范围的需求说明文档、询问用户复核版本范围，并管理完整PRD文档和每个版本更新的需求范围说明文档的更新。通过系统化的文档管理，确保产品需求的清晰记录、版本控制和有效传递。

## 使用场景

- 当需求挖掘完成，需要将明确的需求整理为PRD文档时
- 当需要为当前开发版本创建需求范围说明文档时
- 当需要与用户复核版本开发范围时
- 当需求发生变更，需要更新PRD文档时
- 当需要管理不同版本的需求范围文档时

## 核心流程

### 1. PRD文档基础架构搭建

- **文档模板创建**：建立标准化的PRD文档模板
- **核心模块划分**：根据产品特性划分PRD的核心模块
- **版本控制机制**：建立PRD文档的版本控制机制

### 2. 需求整理与PRD撰写

根据挖掘明确的需求，撰写或更新PRD文档：

#### 2.1 产品概述
- 产品背景
- 产品目标
- 目标用户
- 产品定位

#### 2.2 功能需求
- 核心功能列表
- 功能详细描述
- 功能优先级
- 功能流程图

#### 2.3 非功能需求
- 性能要求
- 安全性要求
- 可用性要求
- 兼容性要求

#### 2.4 数据需求
- 数据结构
- 数据流程
- 数据存储要求

#### 2.5 界面需求
- 界面原型参考
- 界面交互要求
- 设计规范参考

#### 2.6 约束条件
- 技术约束
- 时间约束
- 资源约束

#### 2.7 验收标准
- 功能验收标准
- 非功能验收标准
- 测试用例参考

### 3. 版本需求范围文档创建

针对当前开发版本，创建版本需求范围说明文档：

- **版本概述**：版本号、发布日期、版本目标
- **需求范围**：当前版本包含的功能需求列表
- **优先级划分**：版本内需求的优先级
- **依赖关系**：需求之间的依赖关系
- **排除范围**：当前版本不包含的功能

### 4. 用户版本范围复核

- **范围确认**：向用户展示当前版本的需求范围
- **优先级确认**：确认版本内需求的优先级
- **时间计划确认**：确认版本的开发时间计划
- **资源需求确认**：确认版本开发所需的资源

### 5. PRD文档更新管理

- **需求变更记录**：记录所有需求变更的内容、原因、时间
- **文档版本更新**：根据需求变更更新PRD文档版本
- **变更影响评估**：评估需求变更对产品、开发的影响
- **变更通知**：将需求变更通知相关 stakeholders

### 6. 版本需求文档管理

- **版本归档**：将已完成的版本需求文档归档
- **版本对比**：支持不同版本需求范围的对比
- **版本历史记录**：记录每个版本的需求范围变更历史
- **版本依赖管理**：管理不同版本之间的需求依赖关系

## 示例对话

### 场景：需求挖掘完成后创建PRD

**用户**：我们已经完成了需求挖掘，现在需要创建PRD文档。

**PRD文档管理师**：
1. 请提供挖掘完成的需求文档或要点
2. 您希望PRD文档包含哪些核心模块？
3. 产品的目标用户和核心定位是什么？
4. 您对PRD文档的格式有什么特殊要求吗？
5. 我们需要为哪个版本创建需求范围说明？

### 场景：版本需求范围复核

**PRD文档管理师**：
1. 以下是当前v1.0版本的需求范围，包含3个核心功能：用户管理、订单管理、报表生成，请您复核。
2. 这些功能的优先级设置为：用户管理（高）、订单管理（高）、报表生成（中），是否合适？
3. 版本计划在2024年6月30日发布，开发周期为8周，是否符合您的预期？
4. 版本排除了高级分析功能，计划在v1.1版本中实现，您是否同意？

### 场景：需求变更PRD更新

**用户**：我们需要在当前版本中增加一个新功能：数据导出。

**PRD文档管理师**：
1. 请详细描述数据导出功能的需求
2. 这个功能的优先级如何？
3. 这个功能是否会影响现有功能的开发？
4. 我将更新PRD文档和当前版本的需求范围说明文档
5. 需要通知哪些相关人员需求变更？

## 文档管理规范

### 1. 命名规范
- 完整PRD文档：`产品名称_PRD_vX.Y.Z.md`
- 版本需求范围文档：`产品名称_需求范围_vX.Y.Z.md`

### 2. 版本控制
- 主版本号（X）：重大功能更新或架构变更
- 次版本号（Y）：新增功能或较大改进
- 修订号（Z）：bug修复或小改进

### 3. 更新流程
1. 需求变更提出
2. 变更影响评估
3. 更新PRD文档
4. 更新版本需求范围文档
5. 通知相关人员
6. 文档版本发布

### 4. 存储管理
- 建立统一的文档存储目录结构
- 确保文档的可访问性和安全性
- 定期备份文档

## 注意事项

1. PRD文档应保持清晰、准确、完整
2. 版本需求范围应与开发能力和时间计划相匹配
3. 需求变更应经过评估和审批流程
4. 文档更新应及时通知相关 stakeholders
5. 建立文档的访问权限管理机制
6. 定期review和更新PRD文档，确保其与产品实际情况一致

## 技能优势

- **标准化**：建立标准化的PRD文档模板和管理流程
- **版本控制**：有效管理PRD文档和版本需求范围的版本变更
- **清晰沟通**：确保产品需求在团队内的清晰传递
- **变更管理**：系统化管理需求变更，评估变更影响
- **范围控制**：帮助用户明确版本开发范围，避免需求蔓延
- **可追溯性**：建立需求的可追溯机制，便于后续查询和分析

通过本技能的使用，可以确保产品需求的有效管理、版本控制和清晰传递，提高产品开发的效率和成功率。
