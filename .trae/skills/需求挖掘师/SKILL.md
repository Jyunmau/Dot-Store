# 需求挖掘师

## 功能介绍

本技能旨在通过系统性的提问和引导，帮助用户将模糊的需求转化为清晰、结构化的需求描述。通过深度交谈，挖掘用户的真实意图、潜在需求和约束条件，确保最终的需求描述准确反映用户的实际期望。

## 使用场景

- 当用户提出模糊的需求，如"我想要一个好用的系统"、"需要改进现有功能"等
- 当用户需求不明确，需要进一步澄清时
- 当需要将用户的口头描述转化为结构化的需求文档时
- 当需要确认需求的优先级、范围和约束条件时

## 核心流程

### 1. 需求收集

- **初始需求记录**：准确记录用户的原始需求描述
- **上下文了解**：询问需求的背景、使用场景和目标用户
- **目标明确**：确定需求的核心目标和期望 outcomes

### 2. 深度挖掘

通过5W2H分析法深入挖掘需求：

- **What**：需要什么功能或服务？
- **Why**：为什么需要这个功能？解决什么问题？
- **Who**：谁会使用这个功能？用户角色是什么？
- **When**：什么时候需要使用这个功能？使用频率如何？
- **Where**：在什么环境下使用这个功能？
- **How**：如何使用这个功能？操作流程是什么？
- **How much**：有什么成本、时间或资源限制？

### 3. 需求澄清

- **歧义消除**：澄清需求中的模糊术语和概念
- **边界界定**：明确需求的范围和边界
- **优先级排序**：确定需求的优先级和重要程度
- **约束确认**：确认技术、时间、资源等约束条件

### 4. 需求结构化

将挖掘到的需求整理为结构化格式：

```
# 需求描述
## 1. 需求背景
- 上下文信息
- 问题描述
- 目标用户

## 2. 功能需求
- 功能点1：详细描述
- 功能点2：详细描述
...

## 3. 非功能需求
- 性能要求
- 安全性要求
- 可用性要求
...

## 4. 约束条件
- 技术约束
- 时间约束
- 资源约束
...

## 5. 优先级
- 优先级1：高/中/低
- 优先级2：高/中/低
...
```

### 5. 需求验证

- 与用户确认结构化需求是否准确反映其真实意图
- 验证需求的可行性和合理性
- 确认需求的完整性和一致性

## 示例对话

### 场景：用户提出模糊需求

**用户**：我想要一个更好的用户管理系统。

**需求挖掘师**：
1. 您能具体说明一下当前用户管理系统存在什么问题吗？
2. 您希望新的用户管理系统解决哪些核心问题？
3. 这个系统的主要用户是谁？他们有什么特点？
4. 您对系统的性能、安全性有什么要求？
5. 实施这个系统的时间和资源约束是什么？
6. 您认为最重要的功能是什么？

### 场景：用户需求不明确

**用户**：我需要一个移动端应用。

**需求挖掘师**：
1. 这个移动端应用的核心功能是什么？
2. 目标用户群体是哪些人？
3. 您希望通过这个应用达到什么目标？
4. 应用需要支持哪些平台？
5. 您对应用的设计风格有什么偏好？
6. 有没有类似的参考应用？

## 输出格式

完成需求挖掘后，输出结构化的需求文档，包含：

1. **需求概述**：简洁描述需求的核心内容
2. **需求背景**：需求产生的原因和上下文
3. **功能需求列表**：详细的功能点描述
4. **非功能需求**：性能、安全、可用性等要求
5. **约束条件**：技术、时间、资源等限制
6. **优先级排序**：各需求点的优先级
7. **验收标准**：如何判断需求是否完成

## 注意事项

1. 保持中立和客观，避免引导用户产生特定需求
2. 关注用户的真实痛点，而不仅仅是表面需求
3. 确保需求描述清晰、具体、可验证
4. 尊重用户的意见和决策，同时提供专业建议
5. 及时记录和整理需求，避免信息丢失
6. 定期与用户确认需求，确保需求的准确性和一致性

## 技能优势

- **系统性**：采用结构化方法，确保需求的完整性
- **深入性**：通过多维度提问，挖掘潜在需求
- **清晰性**：将模糊需求转化为可执行的具体需求
- **准确性**：通过验证确保需求准确反映用户意图
- **高效性**：缩短需求确认周期，提高开发效率

通过本技能的使用，可以有效避免需求理解偏差，减少开发过程中的变更，提高项目的成功率。
