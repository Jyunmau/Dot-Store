1. 项目沟通语言：所有交流请使用中文进行。  
2. 代码注释规范：新增注释须用中文撰写，原有英文注释保持不动。  
3. 提交信息：提交说明（commit message）需用中文，简要描述本次改动的目的与范围。  
4. 分支命名：功能分支采用 feat/功能简述，修复分支采用 fix/问题简述，均使用小写与中文字符。  
5. 代码风格：遵循项目既有缩进（2 空格），行宽不超过 120 字符；变量命名采用 camelCase，常量全大写+下划线。  
6. 测试要求：新增业务逻辑须同步提供单元测试，测试文件置于 __tests__ 目录，命名以 .test.js 结尾。  
7. 文档更新：若修改公共 API 或配置，须同步更新 README.md 与 docs/ 下对应文档，保持中英文双语。  
8. 安全检查：提交前执行 npm run lint 与 npm run security，确保无高危漏洞与未处理警告。  
9. 发布流程：master 分支仅通过 MR 合并，合并前至少 1 名同伴 Review 并 CI 通过；版本号遵循 SemVer。  
10. 问题反馈：发现缺陷请新建 Issue，标题前缀【缺陷】，并标注优先级与复现步骤。
