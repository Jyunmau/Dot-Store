# Dot-Store V1.1 开发与测试计划（最终版）

## 1. 设计哲学与功能分层

### 1.1 核心设计哲学

根据 `/Users/jyunmau/Trae-Project/Dot-Store/documents/prd/260118天堂电影酒馆需求及分层架构调整需求.md` 的设计哲学，三层架构的核心原则是：

* **Kernel层**：提供可复用的商业原子能力，保持行业无关性

* **Platform层**：固化行业共识，实现行业特定业务逻辑

* **App/Script层**：提供门店定制能力，支持快速试错

### 1.2 功能分层调整

#### 1.2.1 Order 模块

* **Kernel层**：实现订单的基础逻辑

  * 订单创建、状态更新

  * 基础属性管理

  * 与Event、Ledger的基础集成

* **Platform层**：实现行业特定业务逻辑

  * 购买酒水业务

  * 关联酒台逻辑

  * 行业特定属性扩展

#### 1.2.2 Ledger 模块

* **Kernel层**：实现通用的账本能力

  * 基础账本记录

  * 支持店铺账目管理

  * 新增客户账户管理子模块

  * 保持同时兼容店铺和客户账户

* **Platform层**：实现行业特定账务逻辑

  * 返现计算

  * 积分抵扣

  * 行业特定账目类型

#### 1.2.3 Event 模块

* **Kernel层**：保留通用Event模型

  * 基础事件记录

  * 可扩展的事件属性

  * 支持与Resource的集成扩展点

* **Platform层**：实现ResourceEvent逻辑

  * 资源占用事件

  * 订台相关事件

  * 行业特定事件类型

## 3. 数据迁移计划

### 3.1 迁移策略

* **增量迁移**：保留现有数据，逐步迁移到新架构

* **向后兼容**：旧数据模型与新数据模型并行，确保现有功能正常运行

* **数据验证**：迁移后验证数据一致性

### 3.2 迁移步骤

1. **创建新数据模型**：在现有数据库中创建新的三层架构数据模型
2. **数据映射**：建立旧数据模型到新数据模型的映射关系
3. **编写迁移脚本**：开发数据迁移脚本，将现有数据迁移到新模型
4. **测试验证**：验证迁移后数据的完整性和一致性
5. **逐步切换**：逐步将业务逻辑切换到新数据模型
