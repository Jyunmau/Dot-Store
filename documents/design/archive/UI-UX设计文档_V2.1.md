## 1. 设计概述

### 1.1 设计理念

Dot-Store V2.1 的设计核心理念是**极简设计 + 移动优先 + 品牌化**，旨在为小微餐饮店主提供简洁、高效、易用的经营记录工具。

**核心设计理念：**
1. **极简易用**：界面简洁，去除冗余元素，降低用户认知负担
2. **移动优先**：优先考虑移动端体验，确保在小屏幕上也能高效操作
3. **快速操作**：减少操作步骤，提高记录效率
4. **清晰反馈**：每个操作都有明确的视觉反馈
5. **品牌一致**：统一的品牌视觉元素，建立品牌识别度

### 1.2 目标用户

- **主要用户**：小微餐饮店主（3-10人规模）
- **用户特征**：
  - 年龄：25-45岁
  - 技术能力：一般，会使用智能手机和基本电脑操作
  - 经营压力：大，需要关注现金流
  - 使用场景：店内、移动端为主
- **地域定位**：二三线城市和小县城

### 1.3 设计目标

| 目标维度 | 具体目标 | 衡量指标 |
|---------|---------|----------|
| 易用性 | 学习成本 < 10分钟 | 用户首次使用完成时间 |
| 效率性 | 记录时间 < 30秒 | 平均记录时间 |
| 满意度 | 用户满意度 > 80% | 用户满意度调查 |
| 可访问性 | WCAG 2.1 AA标准 | 无障碍测试评分 |
| 性能 | 页面加载 < 2s | Lighthouse性能评分 |

## 2. 设计原则

### 2.1 核心设计原则

#### 2.1.1 极简设计原则

**原则说明：**
- 界面简洁，去除冗余元素
- 信息层级清晰，重点突出
- 留白充足，避免拥挤

**应用场景：**
- 首页只显示核心信息（今日盈亏、快速记录、今日记录）
- 表单只显示必填字段，可选字段折叠显示
- 导航只显示核心功能（今日、记录、报表、设置）

**设计示例：**
```
首页布局：
┌─────────────────────────────────┐
│  今日盈亏概览（核心信息）      │
├─────────────────────────────────┤
│  快速记录（主要操作）          │
├─────────────────────────────────┤
│  今日记录（辅助信息）          │
└─────────────────────────────────┘
```

#### 2.1.2 移动优先原则

**原则说明：**
- 优先考虑移动端体验
- 触摸目标最小44px×44px
- 避免复杂的手势操作
- 优化单手操作

**应用场景：**
- 底部导航（移动端）vs 侧边导航（桌面端）
- 大按钮（高度48px）vs 小按钮（高度32px）
- 单列布局（移动端）vs 多列布局（桌面端）
- 下拉刷新（移动端）vs 顶部刷新（桌面端）

**设计示例：**
```
移动端导航（底部）：
┌─────────────────────────────────┐
│                              │
│         [页面内容]            │
│                              │
├─────────────────────────────────┤
│  🏠  📝  📊  ⚙️       │
│  今日  记录  报表  设置     │
└─────────────────────────────────┘

桌面端导航（侧边）：
┌────┬─────────────────────────────┐
│ 导 │                            │
│ 航 │      [页面内容]           │
│    │                            │
│ 🏠 │                            │
│ 今日│                            │
│ 📝 │                            │
│ 记录│                            │
│ 📊 │                            │
│ 报表│                            │
│ ⚙️ │                            │
│ 设置│                            │
└────┴─────────────────────────────┘
```

#### 2.1.3 快速操作原则

**原则说明：**
- 减少操作步骤
- 提供快捷操作入口
- 支持批量操作
- 优化表单填写

**应用场景：**
- 快速记录（仅填写必填字段）
- 快速筛选（常用筛选条件置顶）
- 快速导出（一键导出）
- 批量删除（多选删除）

**设计示例：**
```
快速记录流程：
步骤1：填写必填信息（金额、类型）
  ↓
步骤2：点击保存（即可完成）
  ↓
步骤3：后续补充详细信息（可选）
```

#### 2.1.4 清晰反馈原则

**原则说明：**
- 每个操作都有明确的视觉反馈
- 加载状态清晰可见
- 错误提示友好明确
- 成功提示及时出现

**应用场景：**
- 按钮点击：按下效果 + 加载状态
- 表单提交：加载动画 + 成功提示
- 数据加载：骨架屏 + 加载指示器
- 操作错误：错误提示 + 解决方案

**设计示例：**
```
操作反馈流程：
用户点击按钮
  ↓
按钮显示按下效果
  ↓
显示加载动画
  ↓
操作完成
  ↓
显示成功提示（Toast）
  ↓
提示3秒后自动消失
```

#### 2.1.5 品牌一致原则

**原则说明：**
- 统一的品牌色彩
- 统一的图标风格
- 统一的字体系统
- 统一的交互模式

**应用场景：**
- 所有页面使用相同的色彩系统
- 所有图标使用相同的风格（线性/填充）
- 所有标题使用相同的字体和字号
- 所有按钮使用相同的交互效果

### 2.2 用户不是"系统使用者"，而是"生意记录者"

**原则说明：**
- 不要求用户理解ERP/财务/流程
- 不强制完整输入
- 永远允许"先记下来"
- 使用业务语言而非技术语言

**应用场景：**
- 订单记录：使用"订单"而非"销售单"
- 收支记录：使用"收入/支出"而非"应收/应付"
- 状态显示：使用"已完成/待补"而非"已审核/待审核"
- 错误提示：使用"请检查金额"而非"数据验证失败"

**设计示例：**
```
友好提示示例：
❌ 错误：金额格式不正确
✅ 友好：请输入正确的金额格式，如：35.00

❌ 错误：必填字段不能为空
✅ 友好：请填写金额后继续

❌ 错误：数据验证失败
✅ 友好：保存失败，请检查后重试
```

### 2.3 页面 ≠ 功能模块

**原则说明：**
- 页面按用户认知组织
- 后台模块（Order/Ledger/Event）对用户不可见
- 使用业务语言而非技术语言

**应用场景：**
- 今日页面：显示今日盈亏和记录，而非Order和Ledger聚合
- 记录页面：显示订单和收支记录，而非Order和Transaction
- 报表页面：显示报表数据，而非聚合查询结果

**设计示例：**
```
页面组织示例：
用户视角：
- 今日页面：今天发生了什么
- 记录页面：把发生的事情记下来
- 报表页面：看看一段时间的情况
- 设置页面：让系统像我的店

技术视角（隐藏）：
- Order表、Ledger表、Event表
- API接口、数据库查询
- 业务逻辑、数据验证
```

### 2.4 一切围绕「今天」

**原则说明：**
- 今天发生了什么
- 今天赚没赚
- 今天哪里不对

**应用场景：**
- 首页默认显示今日数据
- 报表默认显示今日报表
- 预警提示今日异常
- 快速记录默认记录今天

**设计示例：**
```
首页设计示例：
┌─────────────────────────────────┐
│  今日盈亏概览                │
│  收入：¥1,258  支出：¥832  │
│  盈亏：¥426 ↑ 12%           │
├─────────────────────────────────┤
│  今日发生了什么                │
│  [今日记录列表]               │
├─────────────────────────────────┤
│  快速记录                      │
│  [+ 记一笔]                   │
└─────────────────────────────────┘
```

## 4. 交互流程设计

### 4.1 核心用户操作路径

#### 4.1.1 核心路径 P0（每天必走）

```
打开系统
  ↓
查看「今天」
  ↓
新增一条记录（不完整）
  ↓
晚些时候补充 / 修正
  ↓
查看今天盈亏
```

**交互设计要点：**
- 首页默认显示今日数据
- 快速记录按钮始终可见

### 8.4 数字滚动动画

#### 8.4.1 数字增长动画

```jsx
const AnimatedNumber = ({ value, duration = 1000 }) => {
  const [displayValue, setDisplayValue] = useState(0);
  
  useEffect(() => {
    let startTime;
    let animationFrame;
    
    const animate = (timestamp) => {
      if (!startTime) startTime = timestamp;
      const progress = Math.min((timestamp - startTime) / duration, 1);
      
      const easeOutQuart = 1 - Math.pow(1 - progress, 4);
      const currentValue = Math.floor(value * easeOutQuart);
      
      setDisplayValue(currentValue);
      
      if (progress < 1) {
        animationFrame = requestAnimationFrame(animate);
      }
    };
    
    animationFrame = requestAnimationFrame(animate);
    
    return () => {
      if (animationFrame) {
        cancelAnimationFrame(animationFrame);
      }
    };
  }, [value, duration]);
  
  return (
    <span className="animated-number">
      {displayValue.toLocaleString()}
    </span>
  );
};
```
