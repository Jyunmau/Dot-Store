# Dot-Store V1 UI/UX原型设计说明

## 1. 设计规范解读

### 1.1 核心设计原则

根据PRD文档，Dot-Store的核心设计原则是：
- 记录优先于规范
- 可解释优先于准确
- 修正优先于约束
- 真实世界优先于系统优雅

这些原则将指导整个原型设计过程，确保设计符合产品的核心价值主张。

### 1.2 Figma设计指南应用

我将严格遵循Figma设计指南中的规范，包括：
- **颜色样式**：使用Primary/600 (#1890FF) 作为主色，以及Neutral系列作为中性色
- **文字样式**：使用Heading、Body和Button系列文字样式
- **组件规范**：使用标准的按钮、输入框、卡片等组件
- **网格系统**：采用24列桌面网格、12列表格网格和4列移动网格
- **间距规范**：使用8的倍数作为间距单位

## 2. 页面结构规划

根据PRD文档中的模块划分和用户操作视角，我将设计以下核心页面：

1. **首页（Today）**：显示今日盈亏概览
2. **记录页（Record）**：用于记录订单、收入、支出等事件
3. **分类账页（Ledger）**：查看详细的账务记录
4. **报表页（Report）**：查看历史报表和数据统计
5. **设置页（Setting）**：基础配置和系统设置

## 3. 组件设计

### 3.1 基础组件

我将使用Figma设计指南中的标准组件，并根据Dot-Store的需求进行适当调整：

#### 3.1.1 按钮组件（Button）
- **Primary Button**：用于主要操作，如"保存记录"、"创建订单"
- **Secondary Button**：用于次要操作，如"取消"、"返回"
- **Text Button**：用于辅助操作，如"编辑"、"删除"

#### 3.1.2 输入框组件（Input）
- **Text Input**：用于输入文本信息，如订单名称、金额
- **Number Input**：用于输入数字信息，如金额
- **Select Input**：用于选择选项，如账目类型、标签
- **Date/Time Input**：用于输入日期和时间

#### 3.1.3 卡片组件（Card）
- **统计卡片**：用于显示关键指标，如今日收入、今日支出、今日盈亏
- **记录卡片**：用于显示单条记录，如订单、收入、支出
- **报表卡片**：用于显示报表数据，如收入结构、成本结构

#### 3.1.4 导航组件（Navigation）
- **底部导航栏**：用于移动端页面切换
- **侧边导航栏**：用于桌面端页面切换

### 3.2 复合组件

根据Dot-Store的需求，我将创建以下复合组件：

#### 3.2.1 记录表单组件
- 用于快速记录订单、收入、支出等事件
- 包含金额、类型、标签、备注等字段
- 支持快速保存和后续补充

#### 3.2.2 统计概览组件
- 显示今日盈亏、收入、支出等关键指标
- 使用图表和数字直观展示
- 支持按日期筛选

#### 3.2.3 记录列表组件
- 显示历史记录
- 支持筛选、排序和搜索
- 支持编辑和删除操作

## 5. 交互设计

### 5.1 核心交互流程

#### 5.1.1 记录流程
1. 用户进入首页
2. 点击快速记录按钮（订单、收入、支出）
3. 进入记录页面，填写记录信息
4. 点击保存按钮，记录保存成功
5. 返回首页，查看更新后的统计数据

#### 5.1.2 查看报表流程
1. 用户进入报表页
2. 选择日期范围
3. 查看收入结构和成本结构报表
4. 点击图表或数据可查看详细信息

#### 5.1.3 编辑记录流程
1. 用户进入分类账页
2. 找到需要编辑的记录，点击编辑按钮
3. 进入编辑页面，修改记录信息
4. 点击保存按钮，记录更新成功
5. 返回分类账页，查看更新后的记录

### 5.2 微交互设计

- **按钮悬停效果**：按钮颜色加深，添加轻微阴影
- **输入框聚焦效果**：边框颜色变化，添加轻微阴影
- **页面切换效果**：平滑过渡动画
- **加载状态**：显示加载指示器
- **成功/错误提示**：显示 Toast 提示信息

## 6. 响应式设计

### 6.1 桌面端（≥1200px）
- 使用24列网格系统
- 侧边导航栏布局
- 多列卡片布局

### 6.2 平板端（768px-1199px）
- 使用12列网格系统
- 顶部导航栏+侧边导航栏布局
- 双列卡片布局

### 6.3 移动端（<768px）
- 使用4列网格系统
- 顶部导航栏+底部导航栏布局
- 单列卡片布局
- 响应式表单设计
