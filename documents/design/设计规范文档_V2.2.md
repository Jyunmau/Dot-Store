## 1. 设计原则

### 1.1 核心设计原则

#### 1.1.1 确定性优先原则（V2.2新增）

**原则说明：**
- 让用户看清未来3个月的现金流
- 提供明确的盈亏平衡点
- 给出具体的优化建议
- 建立经营确定性

**设计标准：**
- 仪表盘默认显示现金流预测
- 分析页面提供盈亏平衡分析
- 风险预警提供具体应对建议
- 月报提供优化建议

**应用示例：**
```jsx
// 好的设计：确定性展示
<Dashboard>
  <CashFlowPrediction>
    <PredictionChart data={prediction} />
    <PredictionTable data={prediction} />
    <PredictionAccuracy value={accuracy} />
  </CashFlowPrediction>
</Dashboard>

// 不好的设计：缺乏确定性
<Dashboard>
  <CashFlowBalance value={balance} />
</Dashboard>
```

#### 1.1.2 情绪安全感原则（V2.2新增）

**原则说明：**
- 通过三色仪表盘提供情绪安全感
- 提前预警风险，避免恐慌
- 给出具体行动建议，减少焦虑
- 建立用户信任

**设计标准：**
- 三色仪表盘：绿色安全、黄色注意、红色危险
- 风险预警：提前预警，给出建议
- 月报：提供全面的经营洞察
- 周报：定期提醒，建立习惯

**应用示例：**
```jsx
// 好的设计：情绪安全感
<SafetyIndex score={85}>
  <SafetyZone color="green">
    <Icon name="check-circle" />
    <Text>现金流充足，经营安全</Text>
  </SafetyZone>
</SafetyIndex>

// 不好的设计：缺乏安全感
<SafetyIndex score={85}>
  <Text>安全指数：85分</Text>
</SafetyIndex>
```

#### 1.1.3 极简设计原则（V2.1保留）

**原则说明：**
- 界面简洁，去除冗余元素
- 信息层级清晰，重点突出
- 留白充足，避免拥挤

**设计标准：**
- 页面留白比例 ≥ 30%
- 单屏信息密度 ≤ 60%
- 主要操作按钮 ≤ 3个
- 次要信息可折叠

**应用示例：**
```jsx
// 好的设计：简洁清晰
<Card>
  <CardHeader>现金流概览</CardHeader>
  <CardContent>
    <Stat label="安全指数" value="85分" color="green" />
    <Stat label="现金流余额" value="¥50,000" />
    <Stat label="预测3个月" value="稳定" />
  </CardContent>
</Card>

// 不好的设计：信息过载
<Card>
  <CardHeader>现金流概览</CardHeader>
  <CardContent>
    <Stat label="安全指数" value="85分" />
    <Stat label="现金流余额" value="¥50,000" />
    <Stat label="预测3个月" value="稳定" />
    <Stat label="收入" value="¥10,000" />
    <Stat label="支出" value="¥8,000" />
    <Stat label="净现金流" value="¥2,000" />
  </CardContent>
</Card>
```

#### 1.1.4 移动优先原则（V2.1保留）

**原则说明：**
- 优先考虑移动端体验
- 触摸目标最小44px×44px
- 避免复杂的手势操作
- 优化单手操作

**设计标准：**
- 触摸目标尺寸 ≥ 44px×44px
- 按钮高度 ≥ 48px（移动端）
- 输入框高度 ≥ 48px（移动端）
- 导航高度 ≥ 64px（移动端）

**应用示例：**
```jsx
// 好的设计：触摸目标足够大
<Button height="48px" onClick={handleClick}>
  保存
</Button>

// 不好的设计：触摸目标太小
<Button height="32px" onClick={handleClick}>
  保存
</Button>
```

#### 1.1.5 快速操作原则（V2.1保留）

**原则说明：**
- 减少操作步骤
- 提供快捷操作入口
- 支持批量操作
- 优化表单填写

**设计标准：**
- 核心操作步骤 ≤ 3步
- 表单必填字段 ≤ 5个
- 支持快捷键操作
- 支持批量操作

**应用示例：**
```jsx
// 好的设计：快速记录
<QuickRecord>
  <RecordTypeSelect />
  <AmountInput />
  <SaveButton />
</QuickRecord>

// 不好的设计：复杂表单
<RecordForm>
  <RecordTypeSelect />
  <AmountInput />
  <CustomerInput />
  <AddressInput />
  <PhoneInput />
  <RemarkInput />
  <TagInput />
  <SaveButton />
</RecordForm>
```

#### 1.1.6 清晰反馈原则（V2.1保留）

**原则说明：**
- 每个操作都有明确的视觉反馈
- 加载状态清晰可见
- 错误提示友好明确
- 成功提示及时出现

**设计标准：**
- 按钮点击反馈时间 ≤ 100ms
- 加载状态显示延迟 ≤ 200ms
- 错误提示显示时间 ≤ 500ms
- 成功提示显示时间 ≤ 300ms

**应用示例：**
```jsx
// 好的设计：清晰的反馈
<Button onClick={handleClick} loading={isLoading}>
  {isLoading ? '保存中...' : '保存'}
</Button>

// 不好的设计：无反馈
<Button onClick={handleClick}>
  保存
</Button>
```

#### 1.1.7 品牌一致原则（V2.1保留）

**原则说明：**
- 统一的品牌色彩
- 统一的图标风格
- 统一的字体系统
- 统一的交互模式

**设计标准：**
- 品牌色使用一致
- 图标风格统一（线性/填充）
- 字体系统统一
- 交互模式统一

**应用示例：**
```jsx
// 好的设计：品牌一致
<Button variant="primary" color="primary">
  保存
</Button>
<Icon name="save" variant="outline" />

// 不好的设计：品牌不一致
<Button variant="primary" color="custom">
  保存
</Button>
<Icon name="save" variant="filled" />
```

### 1.2 用户中心原则

#### 1.2.1 用户是"生活方式型主理人"（V2.2升级）

**原则说明：**
- 不要求用户理解财务术语
- 使用业务语言而非技术语言
- 关注用户的情感需求（安全感、确定性）
- 提供智能洞察，而非原始数据

**设计标准：**
- 使用业务语言
- 关注情感需求
- 提供智能洞察
- 友好的错误提示

**应用示例：**
```jsx
// 好的设计：业务语言
<Dashboard>
  <SafetyIndex score={85} />
  <CashFlowPrediction />
  <RiskAlert />
</Dashboard>

// 不好的设计：技术语言
<Dashboard>
  <FinancialHealthScore value={85} />
  <CashFlowForecast />
  <AnomalyDetection />
</Dashboard>
```

#### 1.2.2 页面按用户认知组织（V2.1保留）

**原则说明：**
- 页面按用户认知组织
- 后台模块（Order/Ledger/Event）对用户不可见
- 使用业务语言而非技术语言

**设计标准：**
- 页面按用户认知组织
- 隐藏技术细节
- 使用业务语言

**应用示例：**
```jsx
// 好的设计：用户认知
<Page title="仪表盘">
  <CashFlowOverview />
  <SafetyIndex />
  <RiskAlert />
</Page>

// 不好的设计：技术视角
<Page title="Dashboard">
  <OrderSummary />
  <LedgerSummary />
  <EventSummary />
</Page>
```

#### 1.2.3 一切围绕「现金流安全」（V2.2升级）

**原则说明：**
- 首页默认显示现金流概览
- 分析页面提供现金流预测
- 风险预警提示现金流风险
- 周报月报关注现金流变化

**设计标准：**
- 首页默认显示现金流概览
- 分析页面提供现金流预测
- 风险预警提示现金流风险
- 周报月报关注现金流变化

**应用示例：**
```jsx
// 好的设计：围绕现金流安全
<Page title="仪表盘">
  <CashFlowOverview />
  <SafetyIndex />
  <RiskAlert />
</Page>

// 不好的设计：不围绕现金流安全
<Page title="数据概览">
  <DateRangePicker />
  <Summary />
  <Records />
</Page>
```

## 2. 色彩系统（V2.2优化）

### 2.1 精简色彩系统原则（V2.2新增）

**设计原则**：
- 色彩种类控制在9种以内（7±2法则）
- 避免冗余定义，三色区域和风险等级复用功能色
- 明确色彩优先级和使用场景

**精简后的色彩系统**：
```
基础色（4种）：
- 主色：#3B82F6
- 成功色：#52C41A
- 警告色：#FA541C
- 错误色：#F5222D

三色区域（扩展基础色）：
- 安全区：使用成功色
- 注意区：使用警告色
- 危险区：使用错误色

风险等级（扩展基础色）：
- 高风险：使用错误色
- 中风险：使用警告色
- 低风险：使用警告色（较浅）

中性色（10种）：
- 白色、浅灰1-3、中灰1-3、深灰1-4
```

### 2.2 主色调（V2.1保留）

#### 2.1.1 主色定义

```css
:root {
  --color-primary: #3B82F6;
  --color-primary-light: #DBEAFE;
  --color-primary-dark: #1D4ED8;
  --color-primary-gradient: linear-gradient(135deg, #3B82F6 0%, #2563EB 100%);
}
```

**使用规范：**
- 主色用于主要操作按钮（保存、提交、确认）
- 主色浅用于背景高亮（选中状态、hover状态）
- 主色深用于按钮激活状态（按下状态）
- 主色渐变用于品牌化元素

#### 2.1.2 主色对比度

| 颜色 | 色值 | 对比度（白底） | 是否达标 |
|------|------|--------------|--------|
| 主色 | #3B82F6 | 4.5:1 | ✅ |
| 主色浅 | #DBEAFE | 1.5:1 | ❌ |
| 主色深 | #1D4ED8 | 7.1:1 | ✅ |

**对比度要求：**
- WCAG AA标准：4.5:1
- WCAG AAA标准：7:1
- 主色浅仅用于背景，不用于文字
