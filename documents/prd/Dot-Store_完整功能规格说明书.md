## 1. 产品概述

### 1.1 产品定位

Dot-Store是一个面向生活方式型主理人的经营管理系统，从V2.1的轻量化经营记录与管理工具，演进到V2.2的确定性现金流系统。

**V2.1定位**：轻量化经营记录与管理工具，帮助小微餐饮店主快速记录订单、管理收支、查看报表。

**V2.2定位**：确定性现金流系统，帮助主理人建立现金流确定性，提供情绪安全感。采用三层数据模型架构，实现财务强一致性。

### 1.2 目标用户

- **主要用户**：生活方式型主理人（包括小微餐饮店主、独立设计师、手工店主、课程讲师等）
- **用户特征**：
  - 年龄：25-45岁
  - 技术能力：一般，会使用智能手机和基本电脑操作
  - 经营压力：大，需要关注现金流
  - 经营规模：3-10人
- **地域定位**：二三线城市和小县城

### 1.3 核心价值主张

**V2.1核心价值**：
1. **极简易用**：界面简洁，操作流程简单，学习成本低
2. **快速记录**：支持快速记录订单、收入、支出
3. **实时报表**：提供今日、本周、本月报表，实时了解经营状况
4. **移动优先**：优化移动端体验，支持PWA，随时随地使用
5. **免费核心**：核心功能永久免费，降低使用门槛

**V2.2新增价值**：
1. **现金流确定性**：通过现金流预测和风险预警，提供经营确定性
2. **情绪安全感**：通过三色仪表盘和主动预警，提供情绪安全感
3. **深度洞察**：通过收入结构分析、成本结构分析、归因分析，提供深度经营洞察
4. **持续使用**：通过每周提醒、每月报告、风险预警，引导用户持续使用
5. **财务强一致性**：所有余额可由流水重建，确保数据准确性和可审计性
6. **事件可追溯**：完整的事件日志系统，支持经营行为追溯和分析

### 1.4 版本范围

**V2.1核心功能（基础设施）**：
- 用户认证与权限管理
- 订单管理
- 收支记录
- 报表功能
- 库存预警（简单版）
- 会员积分（简单版）
- 数据备份和恢复
- PWA支持

**V2.2新增功能（三层数据模型架构）**：

**交易事实层（不可篡改）**：

- 库存与成本模块：inventory_transactions、expense_records

**智能分析层（衍生数据）**：

- 收入结构拆解（A1）
- 盈亏平衡点计算（A3）

- 风险提前预警系统（C2）
- 收入波动归因分析（C3）
- 决策日志：decision_logs

**用户持续使用触发机制**：
- 每周现金流提醒（W1）
- 每月健康报告（W2）
- 风险变化提示（W3）
- 用户偏好配置（W4）

**客户端标准化接口预留（F1）**

### 1.5 V2.1到V2.2的过渡方案

#### 1.5.1 架构升级

V2.2在V2.1基础上进行架构升级，采用三层数据模型架构：

```
V2.1数据层（基础）
  ↓
V2.2新增数据层（三层数据模型）
  ↓
交易事实层（不可篡改）
- orders（订单）
- order_items（订单项）
- payments（支付记录）
- inventory_transactions（库存流水）
- customer_account_transactions（账户流水）
- cash_transactions（现金流水）
- business_events（经营事件日志）
  ↓ 驱动
结构状态层（可重建）
- inventory_items（库存状态）
- customer_accounts（客户账户状态）
- cash_accounts（现金账户状态）
- expense_records（成本记录）
- financial_snapshots（财务快照）
  ↓ 读取
智能分析层（衍生数据）
- decision_logs（决策日志）
- cash_flow_predictions（现金流预测）
- risk_alerts（风险预警）
```

#### 1.5.2 数据迁移

**数据映射关系**：

| V2.1数据表 | V2.2目标数据表 | 迁移说明 |
|-----------|--------------|---------|
| orders | orders | 扩展字段，保留原有数据 |
| orders | order_items | 拆分订单明细 |
| transactions | payments | 拆分支付记录 |
| inventory_records | inventory_transactions | 重构为库存流水 |
| inventory | inventory_items | 重构为库存状态 |
| members | customer_accounts | 新增客户账户 |

#### 1.5.3 兼容性保障

- V2.1版本的用户数据完全兼容V2.2版本
- V2.1版本的订单数据完全兼容V2.2版本
- V2.1版本的收支数据完全兼容V2.2版本
- V2.2版本支持从V2.1数据重建三层数据模型

## 2. V2.1核心功能模块

### 2.1 用户认证与权限管理

#### 2.1.1 功能概述

提供用户注册、登录和基于角色的权限管理功能，确保数据安全和用户隔离。

#### 2.1.2 功能需求

**用户注册**
- 支持手机号注册
- 支持邮箱注册
- 支持微信登录（可选）
- 注册时需填写店铺基本信息（店铺名称、店铺类型、所在城市）
- 发送验证码进行手机号验证

**用户登录**
- 支持手机号+密码登录
- 支持邮箱+密码登录
- 支持微信登录（可选）
- 支持记住登录状态（7天）
- 支持忘记密码功能

**权限管理**
- 支持两种角色：店主、店员
- 店主：拥有所有权限
- 店员：仅拥有记录和查看权限，无法删除和导出
- 支持添加/删除店员
- 支持修改店员权限

**数据隔离**
- 不同用户的数据完全隔离
- 店主可以查看所有数据
- 店员只能查看自己创建的数据

#### 2.1.3 非功能性需求

- 密码需加密存储（使用bcrypt）
- 登录失败5次后锁定账户30分钟
- 支持单点登录（同一账号只能在一个设备登录）
- 登录状态过期时间：7天

### 2.2 订单管理

#### 2.2.1 功能概述

提供订单的快速记录、查看和编辑功能，支持订单分类和标签管理。

- 支持按标签筛选

- 订单列表显示：订单号、时间、类型、金额、标签、状态

## 3. V2.2新增功能模块

### 3.1 订单与收入模块（交易事实层）

#### 3.1.1 功能概述

采用规范化设计，将订单、订单项、支付记录分离，符合数据库规范化原则。订单数据作为现金流分析的收入数据源。

**设计原则**：
- 订单（orders）：存储订单基本信息
- 订单项（order_items）：存储订单明细，一个订单可以有多个订单项
- 支付记录（payments）：存储支付信息，一个订单可以有多个支付记录
- 所有订单相关操作写入 business_events 事件日志

**与V2.1的联动**：
- 基于V2.1订单管理功能，拆分为独立的订单、订单项、支付记录表
- 保留V2.1订单录入流程，增加新的字段录入
- 订单数据直接作为现金流分析的收入数据源

#### 3.1.2 订单表（orders）

**收入分类（简化）**
- **产品收入**：销售商品产生的收入
- **服务收入**：提供服务产生的收入（包含会员服务、课程服务、咨询服务等）
- **其他收入**：其他收入（如投资收益、政府补贴等）

**收入模式**
- **一次性收入**：单次交易产生的收入（如商品销售、单次服务）
- **周期性收入**：定期产生的收入（如会员费、订阅费）
- **项目性收入**：项目完成后产生的收入（如培训课程、咨询服务）

**订单录入功能**
- 支持选择收入分类（产品收入/服务收入/其他收入）
- 支持选择收入模式（一次性/周期性/项目性）
- 支持填写客户信息（姓名、手机号、邮箱）
- 记录时自动保存当前时间
- 订单创建时自动写入 business_events 事件日志

#### 3.1.3 订单项表（order_items）

**功能概述**
- 存储订单明细，一个订单可以有多个订单项
- 记录每个订单项的商品、数量、售价、成本价
- 用于计算单品贡献和毛利率

**订单项录入功能**
- 支持添加多个订单项
- 支持选择商品（关联 products 表）
- 支持填写数量、售价、成本价
- 自动计算订单项金额（数量 × 售价）

#### 3.1.4 支付记录表（payments）

**功能概述**
- 存储支付信息，一个订单可以有多个支付记录
- 支持多种支付方式（现金、微信、支付宝、银行卡等）
- 支付记录触发现金流水记录

**支付记录录入功能**
- 支持选择支付方式（现金、微信、支付宝、银行卡等）
- 支持填写支付金额
- 支持填写支付时间
- 支付记录创建时自动触发 cash_transactions 现金流水记录
- 支付记录创建时自动写入 business_events 事件日志

### 3.2 库存与成本模块（交易事实层+结构状态层）

#### 3.2.1 功能概述

采用三层数据模型设计，将库存流水、库存状态、成本记录分离，实现财务强一致性。

**设计原则**：
- 库存流水（inventory_transactions）：记录所有库存变动（不可篡改）
- 库存状态（inventory_items）：库存当前状态（可由流水重建）
- 成本记录（expense_records）：独立成本记录（房租、人工、水电等）
- 所有库存变动必须通过流水驱动
- 库存数量 = sum(inventory_transactions.change_qty)

#### 3.2.2 库存流水表（inventory_transactions）

**变动类型（change_type）**
- **purchase**：采购入库
- **sale**：销售出库
- **adjust**：库存调整
- **refund**：退货入库

**成本分类（多维度）**

**按性质分类**：
- **直接成本**：直接与产品/服务相关的成本
- **间接成本**：间接与产品/服务相关的成本

**按行为分类**：
- **固定成本**：不随业务量变化的成本
- **变动成本**：随业务量变化的成本
- **半变动成本**：部分固定、部分变动的成本

**按功能分类**：
- **生产成本**：生产产品产生的成本
- **销售成本**：销售产品/服务产生的成本
- **管理成本**：管理企业产生的成本
- **财务成本**：融资产生的成本

#### 3.2.3 库存状态表（inventory_items）

**功能概述**
- 存储库存当前状态（数量、平均成本）
- 可由库存流水重建
- 缓存表，提高查询性能

**库存状态计算**
- 库存数量 = sum(inventory_transactions.change_qty)
- 平均成本 = sum(inventory_transactions.变动金额) / sum(inventory_transactions.变动数量)

#### 3.2.4 成本记录表（expense_records）

**功能概述**
- 存储独立成本记录（房租、人工、水电等非库存成本）
- 与库存流水分离，记录间接成本

**成本分类**
- **房租**：门店租金
- **人工**：员工工资、社保
- **水电**：水电费
- **营销**：广告费、推广费
- **财务**：利息、手续费
- **其他**：其他成本

### 3.3 客户账户模块（交易事实层+结构状态层）

#### 3.3.1 功能概述

客户账户模块是系统的核心差异化功能，用于管理预收权益负债。

**设计原则**：
- 客户账户（customer_accounts）：客户预收权益账户状态
- 客户账户流水（customer_account_transactions）：记录客户账户变动
- 预收款 ≠ 收入，是门店负债
- balance_amount 是客户权益，liability_amount 是门店负债

**核心逻辑**：
- 充值时：cash_transactions +income，customer_account_transactions +recharge，liability 增加
- 消费时：customer_account_transactions -consume，liability 减少
- 退款时：cash_transactions -expense，liability 减少

#### 3.3.2 客户账户表（customer_accounts）

- **现金流紧张风险**（低风险）：预计3个月后现金流<3个月支出
- **客户流失率上升风险**（中风险）：客户流失率>历史平均值+20%
- **单一收入来源过高风险**（中风险）：单一收入来源占比>70%
- **成本异常上升风险**（中风险）：成本>历史平均值+30%
- **收入下降风险**（中风险）：收入<历史平均值-20%

**通知方式**
- **站内通知**：在应用内推送风险预警（所有风险）
- **邮件通知**：发送风险预警到用户邮箱（中高风险）
- **短信通知**：发送风险预警到用户手机（高风险）

**用户引导路径**
- **高风险**：查看现金流预测 → 录入新收入 → 查看成本明细 → 查看历史预警 → 标记为已解决
- **中风险**：查看相关分析 → 录入新数据 → 查看历史预警 → 标记为已解决
- **低风险**：查看现金流预测 → 查看历史预警 → 标记为已解决

**风险预警管理**
- 支持查看所有风险预警
- 支持按风险等级筛选（高/中/低）
- 支持按状态筛选（未解决/已解决）
- 支持按时间筛选（近1周/近1个月/近3个月）
- 支持标记预警为已解决
- 支持关闭预警（不再提醒）

#### 3.12.3 非功能性需求

- 风险检测准确率 ≥ 70%
- 风险预警推送延迟 < 5s
- 风险预警误报率 < 10%

### 3.13 用户偏好配置（W4）

#### 3.13.1 功能概述

支持用户自定义触发机制的偏好设置，包括触发频率、推送时间、通知方式等，满足不同用户群体的差异化需求。

#### 3.13.2 功能需求

**配置项**
- **每周现金流提醒配置**：开关、推送时间、推送内容（完整/简化）
- **每月健康报告配置**：开关、生成时间、推送时间、推送方式（站内/站内+邮件）
- **风险预警配置**：开关、通知方式（仅站内/站内+邮件/站内+邮件+短信）、风险等级过滤（全部/仅高风险/仅高+中风险）
- **全局配置**：推送时段（免打扰时段）、推送频率限制（每天最多推送X条）、推送语言（中文/英文）

**用户群体差异化设计**
- **高频用户**（每周活跃≥3次）：开启所有提醒，提供更多深度分析功能
- **中频用户**（每周活跃1-2次）：开启每周提醒和风险预警，关闭每月报告
- **低频用户**（每周活跃<1次）：仅开启风险预警，关闭每周提醒和每月报告
- **新用户**（注册<1个月）：开启所有提醒，提供新手引导

**配置引导**
- **首次使用引导**：用户首次进入设置页面时，提供配置引导
- **配置优化建议**：基于用户行为数据，提供配置优化建议

#### 3.13.3 非功能性需求

- 配置保存响应时间 < 500ms
- 配置实时生效
- 支持配置导入/导出
- 配置界面简洁易用

  ↓

  ↓

## 9. 附录

### 9.1 术语表

| 术语 | 解释 |
|------|------|
| **现金流** | 企业在一定时期内的现金流入和流出情况 |
| **现金流预测** | 基于历史数据预测未来的现金流状况 |
| **盈亏平衡点** | 收入等于成本时的收入水平，超过该点则盈利，低于该点则亏损 |
| **安全指数** | 基于现金流余额和预测收入计算的0-100分指数，表示财务安全程度 |
| **风险预警** | 当检测到现金流风险时，提前预警并给出解决建议 |
| **LTV** | 客户生命周期价值（Lifetime Value），指客户在整个生命周期内为企业带来的总价值 |
| **PWA** | Progressive Web App，渐进式Web应用，支持离线访问和桌面安装 |
| **三层数据模型** | V2.2采用的数据架构，包含交易事实层、结构状态层、智能分析层 |
| **交易事实层** | 记录不可篡改的交易流水，如订单、支付、库存流水、现金流水等 |
| **结构状态层** | 记录可重建的状态数据，如库存状态、客户账户、现金账户、财务快照等 |
| **智能分析层** | 记录衍生分析数据，如决策日志、现金流预测、风险预警等 |
| **财务强一致性** | 所有余额类字段必须可由流水重建，禁止直接修改余额 |
| **事件驱动可追溯** | 所有关键行为写入经营事件日志，支持完整的事件追溯和审计 |
