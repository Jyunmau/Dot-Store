# 微信聊天机器人接入Dot-Store技术可行性报告

## 1. 项目背景与需求分析

### 1.1 项目背景
Dot-Store是一个面向小微实体店铺的轻量化经营记录与理解工具，核心目标是帮助店主轻松记录生意数据、查看经营状况。目前系统采用Web API架构，用户需要通过前端界面或API调用完成业务操作。

### 1.2 需求分析
用户希望通过团队微信群直接联系聊天机器人，完成Dot-Store的核心业务操作，支持：
- 自然语言交互（如"记一笔收入50元"）
- 拍照识别（支持手写或打印的纸质单据）

## 2. 技术可行性分析

### 2.1 微信接入方案

#### 2.1.1 企业微信应用开发（推荐）
**技术方案**：
- 使用企业微信应用开发API实现双向消息交互
- 支持文本消息、图片消息的接收与发送
- 需在企业微信后台注册应用并配置权限

**关键API**：
- 消息接收API：接收用户发送的文本和图片
- 消息发送API：向用户发送处理结果
- 临时素材上传API：处理图片消息

**优势**：
- 官方支持，稳定可靠
- 支持完整的双向消息交互
- 可集成企业微信的其他功能（如通讯录）

**限制**：
- 需要企业微信账号
- 需进行应用注册和配置

#### 2.1.2 群机器人（Webhook）
**技术方案**：
- 使用企业微信群机器人Webhook API

**限制**：
- 仅支持单向发送消息，无法接收用户消息
- 无法实现用户交互功能

**结论**：不适合本需求，仅用于单向通知场景

### 2.2 自然语言处理（NLP）

**技术方案**：
- 使用开源NLP库（如HanLP、jieba）进行中文分词和意图识别
- 构建业务意图分类器（记录收入、记录支出、查询报表等）
- 实现实体提取（金额、日期、标签等）

**示例**：
- 用户输入："记一笔堂食收入58元"
- 意图识别：记录收入
- 实体提取：金额=58元，标签=堂食

**优势**：
- 开发成本低，可快速集成
- 可根据业务需求定制模型
- 响应速度快

**限制**：
- 复杂意图识别准确率有限
- 需要持续优化训练数据

### 2.3 OCR图片识别

**技术方案**：
- 使用开源OCR库（Tesseract-OCR、EasyOCR）处理图片
- 实现图片预处理（灰度化、二值化、去噪）提升识别准确率
- 支持手写和打印文字识别

**技术参数**：
- 基础OCR：识别率约62%
- 优化后：识别率可达94%（需预处理）
- 处理速度：约3-5秒/张

**优势**：
- 开源免费，部署灵活
- 支持多种图片格式
- 可离线使用

**限制**：
- 手写体识别准确率受字体影响
- 复杂背景图片需额外处理

## 3. 系统架构设计

### 3.1 整体架构

```
用户 ←→ 企业微信 ←→ 微信机器人服务 ←→ Dot-Store API
                                   ↓
                               OCR服务
```

### 3.2 模块设计

#### 3.2.1 微信机器人服务
- 消息接收模块：处理企业微信推送的消息
- 消息解析模块：NLP意图识别与实体提取
- 消息发送模块：向用户发送处理结果
- 认证授权模块：处理企业微信API认证

#### 3.2.2 OCR服务
- 图片接收模块：接收并存储用户上传的图片
- 图片预处理模块：提升图片质量
- OCR识别模块：提取图片中的文字信息
- 结果解析模块：结构化识别结果

#### 3.2.3 业务对接模块
- 订单管理：对接Dot-Store的Order API
- 账务管理：对接Dot-Store的Ledger API
- 报表查询：对接Dot-Store的Report API

### 3.3 数据流程

1. 用户在企业微信群发送消息或图片
2. 企业微信将消息推送给微信机器人服务
3. 机器人服务解析消息：
   - 文本消息：NLP意图识别
   - 图片消息：调用OCR服务识别文字
4. 根据识别结果调用Dot-Store API
5. 将处理结果返回给用户

## 4. 技术栈选择

| 模块 | 技术选型 | 理由 |
|------|----------|------|
| 微信机器人服务 | FastAPI | 与现有Dot-Store API服务器技术栈一致，高性能异步框架 |
| NLP处理 | jieba + 自定义规则 | 轻量级，适合简单业务意图识别 |
| OCR服务 | EasyOCR | 开源、支持中文、识别准确率高 |
| 数据库 | PostgreSQL | 与现有系统一致，无需额外部署 |
| 图片存储 | 本地文件系统 | 简化部署，适合小规模应用 |

### 5.3 业务对接示例

```python
# 示例代码：自然语言处理与业务对接
async def handle_text_message(message):
    content = message.get("Content")
    # 1. NLP意图识别
    intent = nlp.recognize_intent(content)
    # 2. 实体提取
    entities = nlp.extract_entities(content)
    # 3. 业务处理
    if intent == "record_income":
        # 调用Dot-Store API创建收入记录
        response = await dotstore_api.create_income(entities)
        return f"收入记录已创建：{response}"
    elif intent == "query_report":
        # 调用Dot-Store API查询报表
        report = await dotstore_api.get_report(entities)
        return f"今日盈亏：{report['profit']}"
    return "抱歉，我不理解您的意思"
```

## 6. 技术风险与应对策略

### 6.1 企业微信API限制
- **风险**：企业微信API有调用频率限制
- **应对**：实现API调用缓存和重试机制，合理控制请求频率

### 6.2 OCR识别准确率
- **风险**：手写体或模糊图片识别准确率低
- **应对**：
  - 实现图片质量检测，对低质量图片提示用户重新拍摄
  - 提供人工修正入口，允许用户调整识别结果
  - 持续优化OCR模型和预处理算法

### 6.3 NLP意图识别
- **风险**：复杂自然语言意图识别不准确
- **应对**：
  - 构建业务专用语料库，持续训练优化
  - 提供标准化输入模板，引导用户使用清晰指令
  - 实现意图确认机制，避免误操作

## 7. 部署与集成方案

### 7.1 部署架构

- **开发环境**：本地开发，使用企业微信沙箱环境测试
- **生产环境**：独立部署微信机器人服务，与Dot-Store API服务器通过内部网络通信

### 7.2 集成方式

- 在现有Dot-Store API基础上扩展微信集成模块
- 使用FastAPI的路由机制，在`/wechat`路径下提供微信机器人相关接口
- 共享现有数据库和业务逻辑，保持数据一致性

## 9. 结论与建议

### 9.1 可行性结论

**技术可行**：
- 企业微信应用开发API支持双向消息交互
- OCR技术可满足手写和打印单据识别需求
- NLP技术可实现基本的自然语言理解
- 与现有Dot-Store架构兼容，集成难度可控

### 9.2 实施建议

1. **分阶段实施**：
   - 第一阶段：实现基础文本消息交互（记录收入/支出）
   - 第二阶段：集成OCR图片识别功能
   - 第三阶段：优化NLP模型，支持更复杂的业务场景

2. **技术选型建议**：
   - 优先使用开源技术，降低成本
   - 考虑使用云OCR服务（如百度OCR、腾讯OCR）提升识别准确率
   - 可结合规则引擎和机器学习模型，平衡开发成本和识别效果

3. **用户体验优化**：
   - 提供清晰的操作指引
   - 实现操作确认机制，避免误操作
   - 支持消息历史记录查询

### 9.3 潜在价值

- 降低用户使用门槛，提升用户体验
- 支持离线场景（通过拍照记录）
- 提高数据记录效率，减少人工录入错误
- 扩展Dot-Store的使用场景，增加用户粘性
