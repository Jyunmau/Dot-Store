## 1. 版本概述

### 1.1 版本信息

- **版本号**：V2.1
- **发布日期**：2026年8月（预计）
- **版本类型**：主要版本更新
- **基于方案**：方案三（聚焦核心方案）

### 1.2 版本目标

本版本聚焦核心功能，旨在：
1. 提供轻量化的店铺管理工具
2. 实现快速记录和实时报表
3. 优化移动端体验
4. 支持离线使用
5. 降低用户使用门槛

### 1.3 目标用户

- **主要用户**：小微餐饮店主（3-10人规模）
- **细分市场**：奶茶店、早餐店、小吃店等微型餐饮业态
- **地域定位**：二三线城市和小县城

### 1.4 核心价值

1. **极简易用**：界面简洁，操作流程简单
2. **快速记录**：支持快速记录订单、收入、支出
3. **实时报表**：提供今日、本周、本月报表
4. **移动优先**：优化移动端体验，支持PWA
5. **免费核心**：核心功能永久免费

## 2. 新增功能说明

### 2.1 用户认证与权限管理

#### 2.1.1 功能描述

新增用户注册、登录和基于角色的权限管理功能，确保数据安全和用户隔离。

#### 2.1.2 功能特性

**用户注册**
- 支持手机号注册
- 支持邮箱注册
- 支持微信登录（可选）
- 注册时需填写店铺基本信息
- 发送验证码进行手机号验证

**用户登录**
- 支持手机号+密码登录
- 支持邮箱+密码登录
- 支持微信登录（可选）
- 支持记住登录状态（7天）
- 支持忘记密码功能

**权限管理**
- 支持两种角色：店主、店员
- 店主：拥有所有权限
- 店员：仅拥有记录和查看权限，无法删除和导出
- 支持添加/删除店员
- 支持修改店员权限

**数据隔离**
- 不同用户的数据完全隔离
- 店主可以查看所有数据
- 店员只能查看自己创建的数据

#### 2.1.3 技术实现

- 使用JWT进行用户认证
- 使用bcrypt进行密码加密
- 实现基于角色的访问控制（RBAC）
- 实现数据隔离中间件

### 2.2 订单分类和标签

#### 2.2.1 功能描述

新增订单分类和标签功能，帮助店主更好地组织和管理订单。

#### 2.2.2 功能特性

**订单分类**

- 支持按分类筛选订单

**订单标签**

- 标签支持增删改查
- 标签在记录订单时可选择（支持多选）
- 支持按标签筛选订单

#### 2.2.3 技术实现

- 设计订单分类表（order_categories）
- 设计订单标签表（order_tags）
- 设计订单-分类关联表（order_category_relations）
- 设计订单-标签关联表（order_tag_relations）
- 实现分类和标签的CRUD接口

### 2.3 收支分类管理

## 7. 已知限制

### 7.1 功能限制

1. **库存管理限制**
   - 仅支持简单的库存记录和预警
   - 不支持复杂的库存管理（如：批次管理、保质期管理）
   - 不支持供应商管理

2. **会员管理限制**
   - 仅支持简单的会员信息和积分管理
   - 不支持复杂的会员体系（如：会员等级晋升、会员营销活动）
   - 不支持会员画像和推荐

3. **报表限制**
   - 仅支持基础报表（今日、本周、本月）
   - 不支持高级报表（如：趋势分析、对比分析）
   - 不支持自定义报表

### 7.2 技术限制

1. **离线限制**
   - 离线时只能查看历史数据
   - 离线记录的数据在联网后自动同步
   - 离线时无法使用导出功能

2. **并发限制**
   - 单个用户最多支持5个并发请求
   - 超过限制的请求会被拒绝
   - 建议用户避免频繁刷新

3. **存储限制**
   - 单个用户的数据存储限制为10GB
   - 超过限制后无法继续记录
   - 建议用户定期导出数据

### 7.3 使用限制

1. **免费功能**
   - 核心功能永久免费
   - 增值功能（如：高级报表、数据分析）需要付费
   - 免费用户有使用次数限制（如：每月导出10次）

2. **付费功能**
   - 付费用户无使用次数限制
   - 付费用户可以使用所有功能
   - 付费用户享有优先技术支持

## 8. 升级指南

### 8.1 从V1.0升级到V2.1

#### 8.1.1 升级前准备

1. **数据备份**
   - 升级前请务必备份数据
   - 导出所有重要数据
   - 保存备份文件到本地

2. **环境检查**
   - 确认服务器环境满足V2.1要求
   - 确认数据库版本兼容
   - 确认Python版本兼容

#### 8.1.2 升级步骤

1. **停止服务**
   ```bash
   docker-compose down
   ```

2. **拉取新版本代码**
   ```bash
   git pull origin v2.1
   ```

3. **更新依赖**
   ```bash
   cd apps/api-server
   pip install -r requirements.txt
   ```

4. **执行数据库迁移**
   ```bash
   docker-compose exec api python -m alembic upgrade head
   ```

5. **启动服务**
   ```bash
   docker-compose up -d
   ```

6. **验证升级**
   - 访问应用，确认功能正常
   - 检查数据是否完整
   - 检查日志是否有错误

#### 8.1.3 升级后验证

1. **功能验证**
   - 测试用户认证功能
   - 测试订单管理功能
   - 测试收支记录功能
   - 测试报表功能

2. **数据验证**
   - 确认订单数据完整
   - 确认收支数据完整
   - 确认报表数据准确

3. **性能验证**
   - 测试页面加载速度
   - 测试API响应速度
   - 测试并发性能

### 8.2 回滚方案

如果升级后出现问题，可以按照以下步骤回滚：

1. **停止服务**
   ```bash
   docker-compose down
   ```

2. **回滚代码**
   ```bash
   git checkout v1.0
   ```

3. **回滚数据库**
   ```bash
   docker-compose exec api python -m alembic downgrade -1
   ```

4. **启动服务**
   ```bash
   docker-compose up -d
   ```

5. **恢复数据**
   - 从备份文件恢复数据
   - 验证数据完整性
