## 1. 版本概述

### 1.1 版本定位

Dot-Store V2.2 是在V2.1轻量化经营记录与管理工具基础上的重大升级，产品定位从"管理工具"转向"确定性现金流系统"。

**核心变化**：
- 产品定位：从"轻量化经营记录与管理工具"转向"确定性现金流系统"
- 核心价值：从"效率"转向"确定性"和"安全感"
- 目标用户：从"小微餐饮店主"扩展到"生活方式型主理人"
- 功能范围：保留V2.1核心功能，新增现金流确定性相关功能
- **架构升级**：采用三层数据模型架构，实现财务强一致性

### 1.2 V2.1基础设施（保留）

V2.1版本的所有核心功能作为基础设施保留，包括：

- 用户认证与权限管理
- 订单管理
- 收支记录
- 报表功能
- 库存预警（简单版）
- 会员积分（简单版）
- 数据备份和恢复
- PWA支持

**详细功能规格请参考**：[Dot-Store 完整功能规格说明书](./Dot-Store_完整功能规格说明书.md) 或 [Dot-Store_V2.1_产品功能规格说明书](./archive/Dot-Store_V2.1_产品功能规格说明书.md)

### 1.3 V2.2架构设计原则

V2.2版本采用**三层数据模型架构**，满足以下4个核心原则：

1. **财务强一致性（可审计）**：所有余额类字段必须可由流水重建，禁止直接修改余额
2. **事件驱动可追溯**：所有关键行为写入经营事件日志，支持完整的事件追溯
3. **支持未来AI推理**：预留完整的AI推理接口，支持AI读取JSON payload
4. **可演进（不推翻重来）**：数据结构支持未来演进，不需要推翻重来

#### 三层数据模型架构

```
┌─────────────────────────────────────────┐
│ 1️⃣ 交易事实层（不可篡改）         │
│ - inventory_transactions（库存流水）   │
│ - customer_account_transactions（账户流水）│
│ - cash_transactions（现金流水）        │
│ - business_events（经营事件日志）      │
└─────────────────────────────────────────┘
              ↓ 驱动
┌─────────────────────────────────────────┐
│ 2️⃣ 结构状态层（可重建）           │
│ - inventory_items（库存状态）         │
│ - customer_accounts（客户账户状态）     │
│ - cash_accounts（现金账户状态）        │
│ - financial_snapshots（财务快照）      │
└─────────────────────────────────────────┘
              ↓ 读取
┌─────────────────────────────────────────┐
│ 3️⃣ 智能分析层（衍生数据）         │
│ - risk_index（风险指数）             │
│ - decision_logs（决策日志）           │
│ - ai_predictions（AI预测）           │
└─────────────────────────────────────────┘
```

### 1.4 V2.2新增功能

V2.2版本新增以下功能模块：

**数据表新增（三层数据模型）**：

**交易事实层**：
- 订单项表（order_items）：独立存储订单明细

- 库存状态表（inventory_items）：库存当前状态
- 客户账户表（customer_accounts）：客户预收权益账户
- 现金账户表（cash_accounts）：现金账户状态
- 成本记录表（expense_records）：独立成本记录
- 财务快照表（financial_snapshots）：每日财务快照

**智能分析层**：
- 决策日志表（decision_logs）：AI建议和人工决策记录
- 现金流预测表（cash_flow_predictions）：现金流预测数据
- 风险预警表（risk_alerts）：风险预警数据

**现金流可视化功能**：
- 现金流可视化仪表盘（C1）

**现金流分析功能**：
- 收入结构拆解（A1）
- 成本结构拆解（A2）
- 盈亏平衡点计算（A3）
- 月度现金流预测模型（A4）

**财务分析功能**：
- 财务指标分析（F1）：毛利率、净利率、库存周转率等
- 财务趋势分析（F2）：同比、环比分析

**风险预警功能**：
- 风险提前预警系统（C2）
- 收入波动归因分析（C3）

**扩展功能**：
- 客户端标准化接口预留（F3）

**用户持续使用触发机制**：
- 每周现金流提醒（W1）
- 每月健康报告（W2）
- 风险变化提示（W3）
- 用户偏好配置（W4）

### 1.5 核心价值主张

1. **现金流确定性**：让主理人看清未来3个月的现金流
2. **情绪安全感**：通过三色仪表盘和风险预警，提供情绪安全感
3. **收入结构优化**：帮助主理人识别收入结构问题，给出优化建议
4. **风险预警**：提前预警现金流风险，避免经营危机
5. **持续使用**：通过每周提醒、每月报告、风险预警，引导用户持续使用
6. **财务强一致性**：所有余额可由流水重建，确保数据准确性和可审计性
7. **事件可追溯**：完整的事件日志系统，支持经营行为追溯和分析

## 2. V2.2新增功能模块

### 2.1 订单与收入模块（交易事实层）

#### 2.1.1 功能概述

采用规范化设计，将订单、订单项、支付记录分离，符合数据库规范化原则。订单数据作为现金流分析的收入数据源。

**设计原则**：
- 订单（orders）：存储订单基本信息
- 订单项（order_items）：存储订单明细，一个订单可以有多个订单项
- 支付记录（payments）：存储支付信息，一个订单可以有多个支付记录
- 所有订单相关操作写入 business_events 事件日志

**与V2.1的联动**：
- 基于V2.1订单管理功能，拆分为独立的订单、订单项、支付记录表
- 保留V2.1订单录入流程，增加新的字段录入
- 订单数据直接作为现金流分析的收入数据源

#### 2.1.2 订单表（orders）

**收入分类（简化）**
- **产品收入**：销售商品产生的收入
- **服务收入**：提供服务产生的收入（包含会员服务、课程服务、咨询服务等）
- **其他收入**：其他收入（如投资收益、政府补贴等）

**收入模式**
- **一次性收入**：单次交易产生的收入（如商品销售、单次服务）
- **周期性收入**：定期产生的收入（如会员费、订阅费）
- **项目性收入**：项目完成后产生的收入（如培训课程、咨询服务）

**服务类型（仅服务收入）**
- **会员服务**：会员充值、续费、会员权益
- **课程服务**：培训课程、在线课程
- **咨询服务**：咨询顾问、专业服务
- **其他服务**：其他服务类型

**订单录入功能**
- 支持选择收入分类（产品收入/服务收入/其他收入）
- 支持选择收入模式（一次性/周期性/项目性）
- 支持选择服务类型（仅服务收入时显示）
- 支持填写客户信息（姓名、手机号、邮箱）
- 支持设置周期性收入参数（周期、金额、开始日期、结束日期）
- 支持设置项目性收入参数（项目名称、项目阶段、里程碑）
- 记录时自动保存当前时间
- 订单创建时自动写入 business_events 事件日志

**订单列表功能**
- 支持按收入分类筛选
- 支持按收入模式筛选
- 支持按服务类型筛选
- 订单列表显示：时间、分类、模式、金额、客户信息、备注
- 支持查看订单的现金流分析数据（毛利率、净利率等）

**订单详情功能**
- 显示订单的收入分类、收入模式、服务类型
- 显示订单的客户信息
- 显示订单的财务指标（毛利率、净利率）
- 显示订单的订单项明细
- 显示订单的支付记录
- 支持编辑订单的扩展字段

#### 2.1.3 订单项表（order_items）

**功能概述**
- 存储订单明细，一个订单可以有多个订单项
- 记录每个订单项的商品、数量、售价、成本价
- 用于计算单品贡献和毛利率

**订单项录入功能**
- 支持添加多个订单项
- 支持选择商品（关联 products 表）
- 支持填写数量、售价、成本价
- 自动计算订单项金额（数量 × 售价）
- 自动计算订单项成本（数量 × 成本价）

**订单项列表功能**
- 显示订单项的商品、数量、售价、成本价、金额
- 支持查看订单项的毛利率

#### 2.1.4 支付记录表（payments）

**功能概述**
- 存储支付信息，一个订单可以有多个支付记录
- 支持多种支付方式（现金、微信、支付宝、银行卡等）
- 支付记录触发现金流水记录

**支付记录录入功能**
- 支持选择支付方式（现金、微信、支付宝、银行卡等）
- 支持填写支付金额
- 支持填写支付时间
- 支付记录创建时自动触发 cash_transactions 现金流水记录
- 支付记录创建时自动写入 business_events 事件日志

**支付记录列表功能**
- 显示支付记录的订单号、支付方式、金额、支付时间
- 支持按支付方式筛选
- 支持按时间范围筛选

#### 2.1.5 非功能性需求

- 订单录入响应时间 < 500ms
- 订单列表加载时间 < 1s
- 订单详情加载时间 < 500ms
- 支付记录创建时必须触发现金流水记录（事务一致性）
- 订单创建时必须写入事件日志（事务一致性）

### 2.2 库存与成本模块（交易事实层+结构状态层）

#### 2.2.1 功能概述

采用三层数据模型设计，将库存流水、库存状态、成本记录分离，实现财务强一致性。

**设计原则**：
- 库存流水（inventory_transactions）：记录所有库存变动（不可篡改）
- 库存状态（inventory_items）：库存当前状态（可由流水重建）
- 成本记录（expense_records）：独立成本记录（房租、人工、水电等）
- 所有库存变动必须通过流水驱动
- 库存数量 = sum(inventory_transactions.change_qty)

**与V2.1的联动**：
- 基于V2.1库存管理功能，拆分为库存流水和库存状态表
- 保留V2.1库存录入流程，增加新的字段录入
- 库存数据直接作为现金流分析的成本数据源

#### 2.2.2 库存流水表（inventory_transactions）

**功能概述**
- 记录所有库存变动（入库、出库、调整、退货）
- 不可篡改的交易事实
- 库存数量由流水聚合计算

**变动类型（change_type）**
- **purchase**：采购入库
- **sale**：销售出库
- **adjust**：库存调整
- **refund**：退货入库

**成本分类（多维度）**

**按性质分类**：
- **直接成本**：直接与产品/服务相关的成本（如原材料、包装）
- **间接成本**：间接与产品/服务相关的成本（如房租、水电）

**按行为分类**：
- **固定成本**：不随业务量变化的成本（如房租、固定人工）
- **变动成本**：随业务量变化的成本（如原材料、包装）
- **半变动成本**：部分固定、部分变动的成本（如水电费、维修费）

**按功能分类**：
- **生产成本**：生产产品产生的成本（如原材料、生产人工）
- **销售成本**：销售产品/服务产生的成本（如包装、运输）
- **管理成本**：管理企业产生的成本（如房租、管理人工）
- **财务成本**：融资产生的成本（如利息、手续费）

**库存流水录入功能**
- 支持选择变动类型（purchase/sale/adjust/refund）
- 支持选择商品（关联 products 表）
- 支持填写变动数量（正数为入库，负数为出库）
- 支持填写单价
- 自动计算变动金额（变动数量 × 单价）
- 支持选择成本性质（直接成本/间接成本）
- 支持选择成本行为（固定成本/变动成本/半变动成本）
- 支持选择成本功能（生产成本/销售成本/管理成本/财务成本）
- 记录时自动保存当前时间
- 库存流水创建时自动写入 business_events 事件日志

**库存流水列表功能**
- 支持按变动类型筛选
- 支持按商品筛选
- 支持按成本分类筛选
- 库存流水列表显示：时间、商品、变动类型、变动数量、单价、金额、成本分类
- 支持查看库存流水的现金流分析数据（成本率、成本趋势等）

#### 2.2.3 库存状态表（inventory_items）

**功能概述**
- 存储库存当前状态（数量、平均成本）
- 可由库存流水重建
- 缓存表，提高查询性能

**库存状态计算**
- 库存数量 = sum(inventory_transactions.change_qty)
- 平均成本 = sum(inventory_transactions.变动金额) / sum(inventory_transactions.变动数量)

**库存状态展示功能**
- 显示商品、当前数量、平均成本、库存价值
- 支持查看库存状态的历史变化
- 支持库存预警（数量低于阈值）

#### 2.2.4 成本记录表（expense_records）

**功能概述**
- 存储独立成本记录（房租、人工、水电等非库存成本）
- 与库存流水分离，记录间接成本

**成本分类**
- **房租**：门店租金
- **人工**：员工工资、社保
- **水电**：水电费
- **营销**：广告费、推广费
- **财务**：利息、手续费
- **其他**：其他成本

**成本记录录入功能**
- 支持选择成本分类
- 支持填写成本金额
- 支持填写成本日期
- 支持填写备注
- 成本记录创建时自动写入 business_events 事件日志

**成本记录列表功能**
- 支持按成本分类筛选
- 支持按时间范围筛选
- 成本记录列表显示：时间、分类、金额、备注

#### 2.2.5 非功能性需求

- 库存流水录入响应时间 < 500ms
- 库存流水列表加载时间 < 1s
- 库存状态加载时间 < 500ms
- 库存数量必须由流水聚合计算（禁止直接修改）
- 库存流水创建时必须写入事件日志（事务一致性）

### 2.3 客户账户模块（交易事实层+结构状态层）

#### 2.3.1 功能概述

客户账户模块是系统的核心差异化功能，用于管理预收权益负债。

**设计原则**：
- 客户账户（customer_accounts）：客户预收权益账户状态
- 客户账户流水（customer_account_transactions）：记录客户账户变动
- 预收款 ≠ 收入，是门店负债
- balance_amount 是客户权益，liability_amount 是门店负债

**核心逻辑**：
- 充值时：cash_transactions +income，customer_account_transactions +recharge，liability 增加
- 消费时：customer_account_transactions -consume，liability 减少
- 退款时：cash_transactions -expense，liability 减少

#### 2.3.2 客户账户表（customer_accounts）

**功能概述**
- 存储客户预收权益账户状态
- 记录客户余额和负债
- 可由账户流水重建

**客户账户字段**
- **balance_amount**：客户权益余额
- **liability_amount**：未履约负债

**客户账户展示功能**
- 显示客户信息、余额、负债
- 支持查看账户流水历史
- 支持查看账户变动趋势

#### 2.3.3 客户账户流水表（customer_account_transactions）

**功能概述**
- 记录客户账户所有变动
- 不可篡改的交易事实
- 账户余额由流水聚合计算

**变动类型（change_type）**
- **recharge**：充值
- **consume**：消费
- **refund**：退款
- **adjust**：调整

**客户账户流水录入功能**
- 支持选择变动类型（recharge/consume/refund/adjust）
- 支持填写变动金额
- 自动更新客户账户余额和负债
- 客户账户流水创建时自动触发 cash_transactions 现金流水记录
- 客户账户流水创建时自动写入 business_events 事件日志

**客户账户流水列表功能**
- 支持按变动类型筛选
- 支持按客户筛选
- 支持按时间范围筛选
- 客户账户流水列表显示：时间、客户、变动类型、变动金额、余额、负债

#### 2.3.4 非功能性需求

- 客户账户流水录入响应时间 < 500ms
- 客户账户流水列表加载时间 < 1s
- 客户账户余额必须由流水聚合计算（禁止直接修改）
- 客户账户流水创建时必须触发相关流水记录（事务一致性）

### 2.4 现金账户模块（交易事实层+结构状态层）

- **payment**：支付记录

**现金流水列表功能**

#### 2.5.1 功能概述

**设计原则**：

#### 2.5.2 财务快照表（financial_snapshots）

**功能概述**
- 每日批量计算生成
- 存储关键财务指标
- 用于AI推理和快速查询

**快照字段**
- **snapshot_date**：快照日期
- **cash_balance**：现金余额
- **total_liability**：总负债（预收未履约负债）
- **inventory_value**：库存价值
- **net_available_cash**：净可用现金（现金余额 - 负债）
- **risk_index**：风险指数

**现金安全度计算逻辑**
```
现金安全余额 = 现金账户余额 - 预收未履约负债 - 未来30天固定成本
```

**风险指数计算公式**
```
风险指数 = (未履约负债 / 现金余额) * 50
         + (库存周转天数 / 60) * 30
         + (近30天收入波动率) * 20
```
标准化为 0-100 分。

**财务快照展示功能**

## 4. 与V2.1基础设施的联动

### 4.1 数据联动架构

#### 4.1.1 三层数据模型架构

V2.2采用三层数据模型架构，在V2.1基础上新增交易事实层和智能分析层，实现财务强一致性。

```
V2.1数据层（基础）
  ↓
V2.2新增数据层（三层数据模型）
  ↓
交易事实层（不可篡改）
- orders（订单）
- order_items（订单项）
- payments（支付记录）
- inventory_transactions（库存流水）
- customer_account_transactions（账户流水）
- cash_transactions（现金流水）
- business_events（经营事件日志）
  ↓ 驱动
结构状态层（可重建）
- inventory_items（库存状态）
- customer_accounts（客户账户状态）
- cash_accounts（现金账户状态）
- expense_records（成本记录）
- financial_snapshots（财务快照）
  ↓ 读取
智能分析层（衍生数据）
- decision_logs（决策日志）
- cash_flow_predictions（现金流预测）
- risk_alerts（风险预警）
```

#### 4.1.2 数据关联关系

**V2.2新增数据表（符合三层数据模型）**：

**交易事实层**：
| 数据表 | 关联V2.1表 | 数据用途 |
|--------|----------|---------|
| orders | V2.1 orders（扩展字段） | 订单基本信息 |
| order_items | V2.1 orders（拆分） | 订单明细，用于计算单品贡献 |
| payments | V2.1 transactions（拆分） | 支付记录，触发现金流水 |
| inventory_transactions | V2.1 inventory_records（重构） | 库存流水，驱动库存状态 |
| customer_account_transactions | 新增 | 客户账户流水，管理预收权益 |
| cash_transactions | 新增 | 现金流水，驱动现金账户 |
| business_events | 新增 | 经营事件日志，AI基础 |

**结构状态层**：
| 数据表 | 关联V2.1表 | 数据用途 |
|--------|----------|---------|
| inventory_items | V2.1 inventory（重构） | 库存状态（可由流水重建） |
| customer_accounts | 新增 | 客户预收权益账户 |
| cash_accounts | 新增 | 现金账户状态 |
| expense_records | 新增 | 独立成本记录 |
| financial_snapshots | 新增 | 每日财务快照 |

**智能分析层**：
| 数据表 | 数据用途 |
|--------|---------|
| decision_logs | AI建议和人工决策记录 |
| cash_flow_predictions | 现金流预测数据 |
| risk_alerts | 风险预警数据 |

**数据单一来源原则**：
- 所有余额类字段必须可由流水重建
- 禁止直接修改余额
- 所有关键行为写入 business_events
- 支持未来接入 AI 读取 JSON payload

- 用户在V2.1中录入库存变动时，自动创建 inventory_transactions 库存流水
- 库存流水创建时自动更新 inventory_items 库存状态
- 库存流水创建时自动写入 business_events 事件日志
- 库存数据直接用于现金流分析、成本结构分析、财务指标分析

**实现方式**：
- 在库存变动页增加变动类型、成本分类等字段
- 库存流水创建时自动更新 inventory_items 库存状态
- 库存流水创建时自动写入 business_events 事件日志
- 库存数量由流水聚合计算（禁止直接修改）

#### 4.2.3 客户账户 → 现金流分析

**联动场景**：
- 用户充值时，自动创建 customer_account_transactions 账户流水
- 账户流水创建时自动触发 cash_transactions 现金流水记录
- 账户流水创建时自动更新 customer_accounts 账户状态
- 账户流水创建时自动写入 business_events 事件日志

**实现方式**：
- 客户充值时创建账户流水（recharge）
- 账户流水创建时自动触发 cash_transactions 现金流水记录
- 账户流水创建时自动更新 customer_accounts 账户余额和负债
- 账户流水创建时自动写入 business_events 事件日志

#### 4.2.4 财务快照 → 现金流仪表盘

**联动场景**：
- 每日定时生成 financial_snapshots 财务快照
- 现金流仪表盘优先从财务快照读取核心指标
- 财务快照数据可由原始数据重建

**实现方式**：
- 每日凌晨2点定时生成财务快照
- 财务快照包含：现金余额、负债、库存价值、净可用现金、风险指数
- 现金流仪表盘优先从财务快照读取核心指标，提高加载速度

### 4.4 数据升级方案

#### 4.4.1 数据升级策略

**数据表结构升级**：
- V2.2创建新的数据表（符合三层数据模型）
- 执行数据库迁移脚本，将V2.1数据迁移到新表
- 保留V2.1的所有数据，确保数据向后兼容

**数据迁移映射**：

| V2.1数据表 | V2.2目标数据表 | 迁移说明 |
|-----------|--------------|---------|
| orders | orders | 扩展字段，保留原有数据 |
| orders | order_items | 拆分订单明细 |
| transactions | payments | 拆分支付记录 |
| inventory_records | inventory_transactions | 重构为库存流水 |
| inventory | inventory_items | 重构为库存状态 |
| members | customer_accounts | 新增客户账户 |

**数据升级流程**：
- 用户首次使用V2.2时，自动执行数据表结构升级
- 升级过程中锁定数据库，确保数据一致性
- 执行数据迁移脚本，将V2.1数据迁移到新表
- 升级完成后自动解锁，用户可以正常使用

#### 4.4.2 数据升级流程

```
用户进入V2.2
  ↓
检测V2.1数据表结构
  ↓
创建V2.2新数据表（三层数据模型）
  ↓
执行数据迁移（V2.1数据 → V2.2新表）
  ↓
执行数据验证（验证数据完整性、一致性）
  ↓
生成初始财务快照
  ↓
显示升级结果（成功/失败）
  ↓
用户进入V2.2首页
```

#### 4.4.3 数据升级验证

**数据完整性验证**：
- 验证升级后的数据表结构是否正确
- 验证升级后的数据数量是否一致
- 验证升级后的数据关联关系是否正确

**数据一致性验证**：
- 验证所有余额是否可由流水重建
- 验证所有关键行为是否写入 business_events
- 验证升级后的数据是否可以正常使用

**数据性能验证**：
- 验证升级后的数据查询性能是否满足要求
- 验证升级后的数据分析性能是否满足要求

**数据回滚机制**：
- 如果升级失败，自动回滚到V2.1数据表结构
- 保留V2.1数据备份，确保数据安全

## 6. 数据结构定义

V2.2采用三层数据模型架构，满足财务强一致性、事件驱动可追溯、支持未来AI推理、可演进的设计原则。

```
┌─────────────────────────────────────────┐
│ 1️⃣ 交易事实层（不可篡改）         │
│ - orders（订单）                      │
│ - order_items（订单项）                │
│ - payments（支付记录）                  │
│ - inventory_transactions（库存流水）   │
│ - customer_account_transactions（账户流水）│
│ - cash_transactions（现金流水）        │
│ - business_events（经营事件日志）      │
└─────────────────────────────────────────┘
              ↓ 驱动
┌─────────────────────────────────────────┐
│ 2️⃣ 结构状态层（可重建）           │
│ - inventory_items（库存状态）         │
│ - customer_accounts（客户账户状态）     │
│ - cash_accounts（现金账户状态）        │
│ - expense_records（成本记录）         │
│ - financial_snapshots（财务快照）      │
└─────────────────────────────────────────┘
              ↓ 读取
┌─────────────────────────────────────────┐
│ 3️⃣ 智能分析层（衍生数据）         │
│ - decision_logs（决策日志）           │
│ - cash_flow_predictions（现金流预测）   │
│ - risk_alerts（风险预警）             │
└─────────────────────────────────────────┘
```

### 7.6 数据一致性需求

#### 7.6.1 核心原则

V2.2采用三层数据模型架构，必须满足以下数据一致性原则：

1. **财务强一致性（可审计）**
   - 所有余额类字段必须可由流水重建
   - 禁止直接修改余额字段
   - 所有余额变更必须通过流水记录触发

2. **事件驱动可追溯**
   - 所有关键行为写入 business_events 事件日志
   - 事件日志不可篡改、不可删除
   - 支持完整的事件追溯和审计

3. **支持未来AI推理**
   - 预留完整的AI推理接口
   - 支持AI读取JSON payload
   - 事件日志包含完整的上下文信息

4. **可演进（不推翻重来）**
   - 数据结构支持未来演进
   - 不需要推翻重来
   - 保持向后兼容性

#### 7.6.2 数据一致性规则

**余额字段一致性规则**：

| 数据表 | 余额字段 | 对应流水表 | 一致性要求 |
|--------|---------|-----------|-----------|
| inventory_items | quantity | inventory_transactions | quantity = SUM(change_qty) |
| customer_accounts | balance | customer_account_transactions | balance = SUM(change_amount) |
| customer_accounts | liability | customer_account_transactions | liability = SUM(待消耗金额) |
| cash_accounts | balance | cash_transactions | balance = SUM(change_amount) |

**禁止操作**：
- 禁止直接修改 inventory_items.quantity
- 禁止直接修改 customer_accounts.balance
- 禁止直接修改 customer_accounts.liability
- 禁止直接修改 cash_accounts.balance
- 禁止删除 inventory_transactions 记录
- 禁止删除 customer_account_transactions 记录
- 禁止删除 cash_transactions 记录
- 禁止删除 business_events 记录

**允许操作**：
- 允许创建 inventory_transactions 记录
- 允许创建 customer_account_transactions 记录
- 允许创建 cash_transactions 记录
- 允许创建 business_events 记录
- 允许通过创建调整记录来修正错误

#### 7.6.3 数据一致性验证

**实时验证**：
- 每次余额变更时，自动验证余额与流水的一致性
- 如果发现不一致，立即记录错误日志并通知管理员
- 提供数据修复工具，支持从流水重建余额

**定时验证**：
- 每日凌晨3点执行全量数据一致性验证
- 验证所有余额字段是否可由流水重建
- 验证所有关键行为是否写入 business_events
- 生成数据一致性报告

**数据一致性报告**：
- 报告内容包括：验证时间、验证结果、不一致数据列表
- 如果发现不一致数据，自动记录到错误日志
- 提供数据修复建议和修复工具

#### 7.6.4 数据一致性保障机制

**事务机制**：
- 所有关键操作使用数据库事务
- 确保流水记录和余额更新的原子性
- 事务失败时自动回滚

**幂等性保障**：
- 所有关键操作支持幂等性
- 使用唯一标识符防止重复操作
- 支持重试机制

**数据备份与恢复**：
- 每日自动备份所有数据
- 备份数据保存至少30天
- 支持从备份恢复数据
- 支持从流水重建余额

**监控与告警**：
- 实时监控数据一致性状态
- 发现不一致时立即告警
- 提供数据修复工具和修复建议

#### 7.6.5 数据一致性测试要求

**单元测试**：
- 测试所有余额变更操作的正确性
- 测试所有流水记录的完整性
- 测试所有事件日志的完整性

**集成测试**：
- 测试跨表数据一致性
- 测试事务回滚机制
- 测试幂等性保障机制

**性能测试**：
- 测试数据一致性验证的性能
- 测试从流水重建余额的性能
- 测试高并发场景下的数据一致性
