## 1. 文档概述

### 1.1 文档分类

本目录下的文档按照以下方式分类：

- **当前版本文档**：当前正在开发的V2.1版本的需求文档
- **归档文档**：V1版本和历史文档，已归档至`archive/`目录

### 1.2 文档命名规范

文档命名遵循以下规范：

- 版本文档：`Dot-Store_V{版本号}_{文档类型}.md`
- 索引文档：`README.md`

### 1.3 文档版本管理

- 文档版本遵循SemVer规范（如：v1.0、v2.1）
- 文档创建日期记录在文档头部
- 文档变更需记录在变更日志中
- 重要变更需更新文档版本号

### 1.4 目录结构

```
documents/prd/
├── README.md                          # 文档索引（本文件）

    ├── PLATFORM_PRD.md                # V1版本Platform层需求
    ├── APP_SCRIPT_PRD.md              # V1版本App/Script层需求
```

## 4. 文档维护规范

### 4.1 文档更新流程

1. **触发条件**
   - 代码实现变更影响文档内容时
   - 设计方案调整时
   - 规范流程变更时
   - 发现文档错误或遗漏时

2. **更新流程**
   - 由相关责任人提出文档更新需求
   - 更新文档内容，确保与实际实现一致
   - 更新文档版本号和变更日志
   - 提交文档更新MR，包含更新说明
   - 由技术负责人审核文档更新
   - 审核通过后合并到主分支

3. **更新要求**
   - 更新内容需准确反映实际实现
   - 更新需保持文档结构清晰、格式统一
   - 重要变更需在文档变更日志中记录
   - 更新后需通知相关团队成员

### 4.2 文档审核

- 文档更新需经过技术负责人审核
- 审核内容包括：准确性、完整性、格式规范性
- 审核通过后才能合并到主分支

### 4.3 文档存储

- 当前版本文档存储在项目的`documents/prd/`目录下
- 历史版本文档归档至`documents/prd/archive/`目录
- 文档需按类型分类存放，保持目录结构清晰
- 历史版本通过Git版本控制管理

### 4.4 文档检索

- 本README.md提供文档索引，方便查阅
- 重要文档需在项目README.md中链接
- 支持通过关键词搜索文档内容

### 4.5 文档版本管理

- 文档需包含版本号，遵循SemVer规范
- 文档变更需记录在变更日志中
- 重大版本更新需发布文档更新通知

### 4.6 文档归档规范

- 当版本升级时，旧版本文档应归档至`archive/`目录
- 归档文档需保留完整内容，不得删除或修改
- 归档操作需在README.md中记录
- 归档后需更新文档索引信息
