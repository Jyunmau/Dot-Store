## 文档内容概要

### 1. 整体架构设计文档_V2.1.md

**主要内容**：
- 架构概述与设计原则
- 技术栈选择与理由
- 模块划分与职责
- 数据库设计
- API 设计
- 前后端架构
- 部署方案
- 安全设计
- 性能优化
- 扩展性规划

**核心要点**：
- 采用多模块单体架构，平衡开发效率与未来扩展性
- 后端使用 FastAPI + PostgreSQL + SQLAlchemy
- 前端使用 React + Zustand + React Query
- 支持 PWA 离线使用
- 数据隔离与权限控制

## 文档使用指南

### 开发人员
1. **架构设计**：参考整体架构设计文档，了解系统架构与技术栈
2. **模块开发**：参考对应模块的技术设计文档，按照设计实现功能
3. **API 对接**：参考接口设计部分，确保前后端对接正确
4. **数据库操作**：参考数据设计部分，正确实现数据库操作

### 测试人员
1. **测试范围**：根据文档中的功能范围，确定测试用例覆盖范围
2. **测试数据**：参考数据设计部分，准备测试数据
3. **API 测试**：参考接口设计部分，设计 API 测试用例

### 产品人员
1. **功能验证**：根据文档中的功能范围，验证产品功能是否完整实现
2. **流程确认**：参考详细逻辑设计部分，确认业务流程是否符合产品需求

## 文档维护

### 更新机制
- 当系统架构发生变更时，更新整体架构设计文档
- 当模块功能发生变更时，更新对应模块的技术设计文档
- 文档版本号与产品版本号保持一致

### 归档规则
- 当文档版本发生变更时，将旧版本文档移动至 archive 目录
- archive 目录下的文档按版本号命名，便于历史查阅
