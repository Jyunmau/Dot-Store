## 文档版本说明

### 当前版本
- **版本号**：V2.2
- **对应产品版本**：Dot-Store V2.2
- **发布日期**：2026年2月
- **架构方案**：三层数据模型架构 + 事件驱动架构

### 版本历史
- **V1.0**：初始版本，采用微服务架构设计
- **V2.1**：多模块单体架构设计，聚焦核心功能
- **V2.2**：三层数据模型架构，新增现金流分析、MCP服务、事件驱动架构

## V2.2版本核心特性

### 架构升级
- **三层数据模型架构**：交易事实层 → 结构状态层 → 智能分析层
- **财务强一致性**：所有余额可由流水重建
- **事件驱动架构**：解耦订单与财务模块，提高系统灵活性
- **并发控制机制**：事务隔离级别、乐观锁、分布式锁

### 新增功能模块
- 现金流预测（7天/30天）
- 风险预警（三色安全指数）
- 盈亏平衡分析
- MCP服务（支持AI Agent调用）
- 事件日志追溯
- 财务快照

### 设计理念升级
- **确定性优先**：让用户看清未来现金流
- **情绪安全感**：三色仪表盘（绿/黄/红）
- **用户语言**：使用业务语言而非技术语言

## 文档使用指南

### 开发人员
1. **架构设计**：参考整体架构设计文档，了解系统架构与技术栈
2. **模块开发**：参考对应模块的技术设计文档，按照设计实现功能
3. **API对接**：参考接口设计部分，确保前后端对接正确
4. **数据库操作**：参考数据设计部分，正确实现数据库操作
5. **优化参考**：参考技术方案评估与优化报告，实现P0/P1优化

### 测试人员
1. **测试范围**：根据文档中的功能范围，确定测试用例覆盖范围
2. **测试数据**：参考数据设计部分，准备测试数据
3. **API测试**：参考接口设计部分，设计API测试用例

### 产品人员
1. **功能验证**：根据文档中的功能范围，验证产品功能是否完整实现
2. **流程确认**：参考详细逻辑设计部分，确认业务流程是否符合产品需求

## 文档维护

### 更新机制
- 当系统架构发生变更时，更新整体架构设计文档
- 当模块功能发生变更时，更新对应模块的技术设计文档
- 文档版本号与产品版本号保持一致

### 归档规则
- 当文档版本发生变更时，将旧版本文档移动至archive目录
- archive目录下的文档按版本号命名，便于历史查阅
