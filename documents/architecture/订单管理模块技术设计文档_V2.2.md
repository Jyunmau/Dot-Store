# 订单管理模块技术设计文档

## 1. 模块概述

订单管理模块是 Dot-Store V2.2 系统的核心业务模块，负责管理店铺的日常订单。该模块基于三层数据模型架构设计，支持订单创建、查询、修改和统计等功能，并与财务模块紧密集成。

**文档版本**：v2.2.1
**最后更新**：2026年2月22日
**修改说明**：本次更新采纳技术方案评估与优化报告建议，实现事件驱动架构解耦订单与财务模块

### 1.1 功能范围

- 订单创建（堂食、外卖、自提）
- 订单查询（列表、详情、筛选）
- 订单修改（金额、备注）
- 订单作废
- 订单统计（日、周、月）
- 订单关联（客户账户、现金账户）

### 1.2 技术栈

- 后端：FastAPI + PostgreSQL + SQLAlchemy
- 前端：React + TypeScript + Zustand
- 数据存储：PostgreSQL（三层数据模型）
- 缓存：Redis

### 1.3 三层数据模型定位

| 层级 | 数据表 | 说明 |
|------|--------|------|
| 交易事实层 | `orders` | 订单主表，记录订单交易 |
| 结构状态层 | `daily_order_summaries` | 每日订单汇总 |
| 智能分析层 | `order_trends` | 订单趋势分析数据 |

### 1.4 V2.2版本变更

| 变更项 | V2.1 | V2.2 | 变更说明 |
|--------|------|------|----------|
| 订单类型 | 堂食、外卖 | 堂食、外卖、自提 | 新增自提类型 |
| 客户关联 | 无 | 支持 | 支持关联客户账户消费 |
| 现金关联 | 无 | 支持 | 订单完成自动记录现金收入 |
| 事件日志 | 无 | 支持 | 订单操作记录到事件日志 |
| **事件驱动** | 直接调用 | 事件发布订阅 | 解耦订单与财务模块（P0优化） |

#### 2.2.2 Zustand 状态管理

```typescript
// src/store/orderStore.ts
import { create } from 'zustand';
import { Order, OrderCreate, OrderSummary } from '../types/order';
import { orderApi } from '../services/orderService';

interface OrderState {
  orders: Order[];
  currentOrder: Order | null;
  todaySummary: OrderSummary | null;
  isLoading: boolean;
  error: string | null;
  
  createOrder: (data: OrderCreate) => Promise<Order>;
  getOrders: (filters?: { date?: string; order_type?: string }) => Promise<void>;
  getOrder: (id: number) => Promise<void>;
  voidOrder: (id: number, reason: string) => Promise<void>;
  getTodaySummary: () => Promise<void>;
  clearError: () => void;
}

const useOrderStore = create<OrderState>((set, get) => ({
  orders: [],
  currentOrder: null,
  todaySummary: null,
  isLoading: false,
  error: null,
  
  createOrder: async (data: OrderCreate) => {
    set({ isLoading: true, error: null });
    try {
      const order = await orderApi.createOrder(data);
      set((state) => ({
        orders: [order, ...state.orders],
        isLoading: false
      }));
      return order;
    } catch (error) {
      set({ error: error instanceof Error ? error.message : '创建订单失败', isLoading: false });
      throw error;
    }
  },
  
  voidOrder: async (id: number, reason: string) => {
    set({ isLoading: true, error: null });
    try {
      await orderApi.voidOrder(id, reason);
      set((state) => ({
        orders: state.orders.map(o => 
          o.id === id ? { ...o, status: 'voided', is_deleted: true } : o
        ),
        isLoading: false
      }));
    } catch (error) {
      set({ error: error instanceof Error ? error.message : '作废订单失败', isLoading: false });
    }
  },
  
  getTodaySummary: async () => {
    try {
      const summary = await orderApi.getTodaySummary();
      set({ todaySummary: summary });
    } catch (error) {
      console.error('获取今日汇总失败:', error);
    }
  },
  
  clearError: () => set({ error: null }),
}));

export default useOrderStore;
```

## 5. 详细逻辑设计

### 5.1 创建订单流程

#### 5.1.1 事件驱动架构（P0优化）

V2.2版本采用事件驱动架构解耦订单模块与财务模块：

```python
# app/services/order_service.py
from app.core.event_bus import event_bus, DomainEvent

async def create_order(user_id: int, data: OrderCreate) -> Order:
    """
    创建订单 - 使用事件驱动架构
    
    优化说明：
    - 订单模块只负责订单本身的创建
    - 财务关联通过事件发布订阅实现
    - 降低模块耦合度，提高系统灵活性
    """
    async with db.transaction():
        # 1. 生成订单编号
        order_no = generate_order_no()
        
        # 2. 创建订单记录
        order = Order(
            user_id=user_id,
            order_no=order_no,
            order_type=data.order_type,
            amount=data.amount,
            payment_method=data.payment_method,
            customer_account_id=data.customer_account_id,
            note=data.note,
            status='completed',
            created_by=get_current_user_id()
        )
        
        # 3. 保存订单
        await db.save(order)
        
        # 4. 发布订单完成事件（替代直接调用财务模块）
        event = DomainEvent(
            event_type="order_completed",
            aggregate_type="order",
            aggregate_id=order.id,
            payload={
                "order_no": order_no,
                "amount": float(data.amount),
                "payment_method": data.payment_method,
                "customer_account_id": data.customer_account_id,
                "user_id": user_id,
                "created_at": order.created_at.isoformat()
            }
        )
        await event_bus.publish(event)
        
        return order
```

from app.core.event_bus import event_bus

@event_bus.subscribe("order_completed")
async def handle_order_completed_for_cash(event: DomainEvent):
    """
    处理订单完成事件 - 记录现金收入
    
    订阅者：现金账户模块
    触发条件：现金支付订单完成
    """
    if event.payload["payment_method"] == "cash":

# app/services/customer_service.py
@event_bus.subscribe("order_completed")
async def handle_order_completed_for_customer(event: DomainEvent):
    """
    处理订单完成事件 - 扣减客户余额
    
    订阅者：客户账户模块
    触发条件：会员支付订单完成
    """

#### 5.1.3 传统实现（保留作为参考）

```python
async def create_order_traditional(user_id: int, data: OrderCreate) -> Order:
    """
    创建订单 - 传统直接调用方式（已废弃）
    
    问题：
    - 订单模块直接依赖现金账户模块和客户账户模块
    - 模块耦合度高，难以维护和扩展
    """
    async with db.transaction():
        # 1. 生成订单编号
        order_no = generate_order_no()
        
        # 2. 创建订单记录
        order = Order(
            user_id=user_id,
            order_no=order_no,
            order_type=data.order_type,
            amount=data.amount,
            payment_method=data.payment_method,
            customer_account_id=data.customer_account_id,
            note=data.note,
            status='completed',
            created_by=get_current_user_id()
        )
        
        # 3. 处理支付方式（直接调用 - 高耦合）
        if data.payment_method == PaymentMethod.CASH:
            # 现金支付：记录现金收入
            cash_tx = await cash_service.record_income(
                user_id=user_id,
                amount=data.amount,
                category='order_income',
                note=f'订单收入: {order_no}',
                order_id=order.id
            )
            order.cash_transaction_id = cash_tx.id
            
        elif data.payment_method == PaymentMethod.CUSTOMER_ACCOUNT:
            # 会员账户支付：扣减客户余额
            if not data.customer_account_id:
                raise ValueError('会员支付需要指定客户账户')
            
            customer_tx = await customer_service.consume(
                user_id=user_id,
                account_id=data.customer_account_id,
                amount=data.amount,
                order_id=order.id,
                note=f'订单消费: {order_no}'
            )
        
        # 4. 保存订单
        await db.save(order)
        
        # 5. 记录事件日志
        await event_log_service.log(
            event_type='order_created',
            entity_type='order',
            entity_id=order.id,
            data={'order_no': order_no, 'amount': str(data.amount)}
        )
        
        return order
```

### 5.2 作废订单流程

```python
async def void_order(user_id: int, order_id: int, reason: str) -> Order:
    """
    作废订单 - 包含财务冲正逻辑
    """
    async with db.transaction():
        # 1. 获取订单
        order = await db.get_order(user_id, order_id)
        if not order or order.is_deleted:
            raise OrderNotFoundError('订单不存在或已作废')
        
        # 2. 处理财务冲正
        if order.payment_method == PaymentMethod.CASH and order.cash_transaction_id:
            # 现金支付：记录退款支出
            await cash_service.record_expense(
                user_id=user_id,
                amount=order.amount,
                category='refund_income',
                note=f'订单作废退款: {order.order_no}, 原因: {reason}'
            )
            
        elif order.payment_method == PaymentMethod.CUSTOMER_ACCOUNT and order.customer_account_id:
            # 会员支付：退回余额
            await customer_service.recharge(
                user_id=user_id,
                account_id=order.customer_account_id,
                amount=order.amount,
                note=f'订单作废退款: {order.order_no}, 原因: {reason}'
            )
        
        # 3. 更新订单状态
        order.is_deleted = True
        order.status = 'voided'
        order.deleted_at = datetime.now()
        order.deleted_by = get_current_user_id()
        
        # 4. 保存
        await db.save(order)
        
        # 5. 记录事件日志
        await event_log_service.log(
            event_type='order_voided',
            entity_type='order',
            entity_id=order.id,
            data={'order_no': order.order_no, 'reason': reason}
        )
        
        return order
```

### 5.3 边缘场景处理

| 场景 | 处理方式 |
|------|----------|
| 余额不足 | 会员支付时检查余额，不足则拒绝 |
| 订单已作废 | 作废操作检查订单状态，已作废则拒绝 |
| 并发创建 | 使用数据库事务保证原子性 |
| 当日汇总 | 使用Redis缓存，订单变更时更新 |

## 6. 实现注意事项

### 6.1 后端实现注意事项

- 订单创建必须在数据库事务中执行
- 支付方式处理需要与财务模块协调
- 订单作废需要处理财务冲正
- 记录所有关键操作到事件日志

### 6.2 前端实现注意事项

- 订单创建后刷新汇总数据
- 支付方式选择联动客户账户
- 作废操作需要确认
- 金额输入使用 InputNumber 组件

### 6.3 安全注意事项

- 订单操作需要相应权限
- 作废操作需要二次确认
- 敏感操作记录到事件日志
