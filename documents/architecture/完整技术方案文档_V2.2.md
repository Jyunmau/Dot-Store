## 3. 三层数据模型架构

### 3.1 架构设计原则

三层数据模型架构是 V2.2 版本的核心架构改进，确保财务数据的强一致性和可追溯性。

```
┌─────────────────────────────────────────────────────────────────┐
│                     智能分析层 (Analytics Layer)                 │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐  │
│  │ financial_trends │  │ cash_flow_analyses│  │ stock_value_hist │  │
│  │ 订单趋势分析      │  │ 现金流分析        │  │ 库存价值历史     │  │
│  └─────────────────┘  └─────────────────┘  └─────────────────┘  │
│  特点：派生数据、可重建、支持复杂查询                            │
└─────────────────────────────────────────────────────────────────┘
                              ▲
                              │ 派生
┌─────────────────────────────────────────────────────────────────┐
│                     结构状态层 (State Layer)                     │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐  │
│  │ customer_accounts│  │   cash_accounts  │  │ financial_snap  │  │
│  │ 客户账户状态      │  │ 现金账户状态      │  │ 财务快照        │  │
│  └─────────────────┘  └─────────────────┘  └─────────────────┘  │
│  特点：可重建状态、缓存优化、定期同步                            │
└─────────────────────────────────────────────────────────────────┘
                              ▲
                              │ 更新
┌─────────────────────────────────────────────────────────────────┐
│                     交易事实层 (Transaction Layer)               │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐  │
│  │customer_transacts│  │ cash_transactions│  │stock_transactions│  │
│  │ 客户交易记录      │  │ 现金交易记录      │  │ 库存交易记录     │  │
│  └─────────────────┘  └─────────────────┘  └─────────────────┘  │
│  特点：不可变、追加写入、完整审计追踪                            │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 数据一致性保证

| 机制 | 说明 |
|------|------|
| 交易不可变 | 所有交易记录一旦创建不可修改、不可删除 |
| 状态可重建 | 所有状态层数据可从交易记录重建 |
| 事务原子性 | 所有写操作在数据库事务中执行 |
| 乐观锁控制 | 使用版本号防止并发冲突 |
| 定期校验 | 定时任务校验状态与交易一致性 |

### 3.3 各模块数据模型映射

| 模块 | 交易事实层 | 结构状态层 | 智能分析层 |
|------|------------|------------|------------|
| 客户账户 | `customer_transactions` | `customer_accounts` | `customer_balance_history` |
| 现金账户 | `cash_transactions` | `cash_accounts` | `cash_balance_history` |
| 库存 | `stock_transactions` | `ingredients` | `stock_value_history` |
| 订单 | `orders` | `daily_order_summaries` | `order_trends` |
| 财务 | - | `financial_snapshots` | `financial_trends` |
| 现金流 | - | `cash_flow_forecasts` | `cash_flow_analyses` |

## 5. 接口设计规范

### 5.1 API版本控制

| 版本 | 状态 | 说明 |
|------|------|------|
| v1 | 稳定 | V2.1及之前版本接口 |
| v2 | 开发中 | V2.2新接口，支持三层数据模型 |

### 5.2 统一响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... },
  "timestamp": "2026-02-22T10:00:00Z"
}
```

### 5.3 错误码规范

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未认证 |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 409 | 资源冲突 |
| 422 | 业务逻辑错误 |
| 500 | 服务器内部错误 |

### 5.4 认证方式

| 方式 | 适用场景 | 说明 |

| JWT Token | 前端用户 | Authorization: Bearer {token} |
| API Key | MCP服务 | X-API-Key: {api_key} |

## 7. 安全设计

### 7.1 认证安全

- 密码使用 bcrypt 加密存储
- JWT Token 有效期控制
- 登录失败限制（5次锁定30分钟）
- API密钥仅显示一次

### 7.2 权限控制

- 基于角色的访问控制（RBAC）
- 细粒度权限定义
- 接口级别权限检查
- 数据隔离（按用户ID）

### 7.3 数据安全

- 敏感数据脱敏存储
- 交易记录不可修改
- 操作审计日志
- 定期数据备份

### 7.4 接口安全

- HTTPS 强制加密
- 请求频率限制
- 参数验证
- SQL注入防护

## 8. 性能优化方案

### 8.1 数据库优化

- 合理使用索引
- 大表分区
- 查询优化
- 连接池配置

### 8.2 缓存策略

| 缓存内容 | 缓存时间 | 说明 |
|----------|----------|------|
| 用户权限 | 30分钟 | 权限变更后刷新 |
| 今日订单汇总 | 1分钟 | 订单变更后刷新 |
| 库存预警 | 5分钟 | 库存变更后刷新 |
| 会话状态 | 24小时 | 会话活跃时刷新 |

### 8.3 异步处理

| 任务 | 处理方式 | 说明 |
|------|----------|------|
| 事件日志记录 | 异步队列 | 不影响主业务 |
| 财务快照生成 | 定时任务 | 每日凌晨执行 |
| 现金流预测 | 后台任务 | 请求触发后异步计算 |
| 数据导出 | 异步任务 | 大数据量导出 |

## 9. 部署方案

### 9.1 容器化部署

```yaml
# docker-compose.yml
services:
  api-server:
    build: ./apps/api-server
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://...
      - REDIS_URL=redis://...
    depends_on:
      - postgres
      - redis

  web-app:
    build: ./apps/web-app
    ports:
      - "3000:80"
    depends_on:
      - api-server

  postgres:
    image: postgres:15
    volumes:
      - postgres_data:/var/lib/postgresql/data

  redis:
    image: redis:7
    volumes:
      - redis_data:/data
```

## 11. 风险评估

### 11.1 技术风险

| 风险 | 等级 | 应对措施 |
|------|------|----------|
| 三层数据模型复杂度 | 中 | 充分测试、文档完善 |
| 并发数据一致性 | 高 | 事务控制、锁机制 |
| 性能瓶颈 | 中 | 缓存优化、异步处理 |
| MCP协议兼容性 | 低 | 参考官方规范 |

### 11.2 业务风险

| 风险 | 等级 | 应对措施 |
|------|------|----------|
| 数据迁移 | 高 | 制定迁移方案、充分测试 |
| 用户习惯变更 | 中 | 用户培训、文档支持 |
| 功能遗漏 | 低 | 需求确认、测试覆盖 |

### 11.3 风险应对策略

1. **数据迁移风险**
   - 制定详细迁移方案
   - 编写迁移脚本
   - 搭建测试环境验证
   - 准备回滚方案

2. **并发一致性风险**
   - 使用数据库事务
   - 实现乐观锁机制
   - 定期数据校验
   - 异常告警机制

3. **性能风险**
   - 压力测试
   - 性能监控
   - 优化方案储备
