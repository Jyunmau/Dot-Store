# 客户账户模块技术设计文档

## 1. 模块概述

客户账户模块是 Dot-Store V2.2 系统新增的核心财务模块，负责管理客户预付款账户、预收权益负债追踪和客户消费记录。该模块基于三层数据模型架构设计，确保财务数据的强一致性和可追溯性。

### 1.1 功能范围

- 客户账户管理（创建、查询、更新）
- 预付款充值（记录充值交易、更新负债）
- 消费扣款（订单消费、余额扣减）
- 余额查询（实时余额、可重建余额）
- 充值记录查询
- 消费记录查询

### 1.2 技术栈

- 后端：FastAPI + PostgreSQL + SQLAlchemy
- 前端：React + TypeScript + Zustand
- 数据存储：PostgreSQL（三层数据模型）
- 缓存：Redis（账户余额缓存）

### 1.3 三层数据模型定位

| 层级 | 数据表 | 说明 |
|------|--------|------|
| 交易事实层 | `customer_transactions` | 不可变的交易记录，所有充值和消费记录 |
| 结构状态层 | `customer_accounts` | 可重建的账户状态，当前余额 |
| 智能分析层 | `customer_balance_history` | 余额历史趋势分析数据 |

### 1.4 V2.2版本新增功能

| 功能 | 说明 |
|------|------|
| 预收权益负债 | 准确追踪客户预付款形成的负债 |
| 余额可重建 | 所有余额可从交易记录重建，确保数据一致性 |
| 交易不可变 | 所有交易记录不可修改、不可删除 |
| 事件溯源 | 关键操作记录到业务事件日志 |

import { create } from 'zustand';
import { CustomerAccount, CustomerTransaction, RechargeParams, ConsumeParams } from '../types/customer';
import { customerApi } from '../services/customerService';

interface CustomerState {
  accounts: CustomerAccount[];
  currentAccount: CustomerAccount | null;
  transactions: CustomerTransaction[];
  isLoading: boolean;
  error: string | null;
  
  createAccount: (data: { customer_name: string; phone: string }) => Promise<void>;
  getAccounts: () => Promise<void>;
  getAccount: (id: number) => Promise<void>;
  getAccountByPhone: (phone: string) => Promise<CustomerAccount | null>;
  recharge: (params: RechargeParams) => Promise<void>;
  consume: (params: ConsumeParams) => Promise<void>;
  getTransactions: (accountId: number) => Promise<void>;
  clearError: () => void;
}

const useCustomerStore = create<CustomerState>((set, get) => ({
  accounts: [],
  currentAccount: null,
  transactions: [],
  isLoading: false,
  error: null,
  
  createAccount: async (data) => {
    set({ isLoading: true, error: null });
    try {
      const account = await customerApi.createAccount(data);
      set((state) => ({
        accounts: [...state.accounts, account],
        isLoading: false
      }));
    } catch (error) {
      set({ error: error instanceof Error ? error.message : '创建账户失败', isLoading: false });
    }
  },
  
  recharge: async (params: RechargeParams) => {
    set({ isLoading: true, error: null });
    try {
      const transaction = await customerApi.recharge(params);
      set((state) => ({
        currentAccount: state.currentAccount?.id === params.account_id
          ? { ...state.currentAccount, balance: transaction.balance_after, total_recharged: state.currentAccount.total_recharged + params.amount }
          : state.currentAccount,
        transactions: [transaction, ...state.transactions],
        isLoading: false
      }));
    } catch (error) {
      set({ error: error instanceof Error ? error.message : '充值失败', isLoading: false });
    }
  },
  
  consume: async (params: ConsumeParams) => {
    set({ isLoading: true, error: null });
    try {
      const transaction = await customerApi.consume(params);
      set((state) => ({
        currentAccount: state.currentAccount?.id === params.account_id
          ? { ...state.currentAccount, balance: transaction.balance_after, total_consumed: state.currentAccount.total_consumed + params.amount }
          : state.currentAccount,
        transactions: [transaction, ...state.transactions],
        isLoading: false
      }));
    } catch (error) {
      set({ error: error instanceof Error ? error.message : '消费失败', isLoading: false });
    }
  },
  
  // ... 其他方法实现
}));

export default useCustomerStore;

#### 3.3.2 余额重建机制

```python
async def rebuild_balance(account_id: int) -> Decimal:
    """
    从交易记录重建余额 - 用于数据校验和修复
    """
    # 计算所有交易的余额变化
    result = await db.query("""
        SELECT 
            COALESCE(SUM(CASE WHEN transaction_type IN ('recharge', 'refund', 'adjust_add') 
                THEN amount ELSE -amount END), 0) as calculated_balance
        FROM customer_transactions
        WHERE account_id = $1
    """, account_id)
    
    calculated_balance = result[0]['calculated_balance']
    
    # 更新账户余额
    await db.execute("""
        UPDATE customer_accounts 
        SET balance = $1, updated_at = NOW()
        WHERE id = $2
    """, calculated_balance, account_id)
    
    return calculated_balance
```

## 5. 详细逻辑设计

### 5.1 充值流程

1. 前端提交充值请求（账户ID、金额、备注）
2. 后端验证用户权限
3. 验证账户状态和金额有效性
4. 开启数据库事务
5. 获取账户记录并加锁（SELECT FOR UPDATE）
6. 记录交易前余额
7. 更新账户余额和累计充值金额
8. 创建交易记录
9. 记录业务事件日志
10. 提交事务
11. 更新Redis缓存
12. 返回交易结果

### 5.2 消费流程

1. 前端提交消费请求（账户ID、金额、订单ID）
2. 后端验证用户权限
3. 验证账户状态和余额充足
4. 开启数据库事务
5. 获取账户记录并加锁
6. 验证余额充足
7. 记录交易前余额
8. 扣减账户余额，增加累计消费金额
9. 创建交易记录
10. 记录业务事件日志
11. 提交事务
12. 更新Redis缓存
13. 返回交易结果

### 5.3 余额校验流程

1. 定时任务每日凌晨执行
2. 遍历所有活跃账户
3. 从交易记录计算应有余额
4. 与账户表余额对比
5. 发现不一致时记录日志并告警
6. 可选自动修复

### 5.4 边缘场景处理

| 场景 | 处理方式 |
|------|----------|
| 余额不足 | 返回错误，拒绝消费 |
| 并发操作 | 使用乐观锁+行锁，失败时重试 |
| 账户冻结 | 拒绝所有交易操作 |
| 交易回滚 | 数据库事务自动回滚 |
| 余额不一致 | 记录告警，支持手动/自动重建 |

          <Input.TextArea />
        </Form.Item>
      </Form>
    </Modal>
  );
};

export default CustomerRecharge;

## 7. 实现注意事项

### 7.1 后端实现注意事项

- 所有交易操作必须在数据库事务中执行
- 使用行锁防止并发问题
- 交易记录不可修改、不可删除
- 金额使用 Decimal 类型，避免浮点精度问题
- 记录所有关键操作到业务事件日志

### 7.2 前端实现注意事项

- 金额输入使用 InputNumber 组件，设置精度
- 充值/消费前确认账户状态
- 显示交易前后余额变化
- 支持交易记录分页加载

### 7.3 安全注意事项

- 充值/消费操作需要相应权限
- 大额交易需要二次确认
- 敏感操作记录到事件日志
- 定期执行余额校验
