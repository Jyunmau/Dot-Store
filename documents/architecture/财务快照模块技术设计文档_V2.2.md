# 财务快照模块技术设计文档

## 1. 模块概述

财务快照模块是 Dot-Store V2.2 系统新增的核心财务模块，负责定期生成财务状态快照，提供财务数据的时间点视图。该模块确保财务数据的完整性和可追溯性，支持财务分析和报表生成。

### 1.1 功能范围

- 自动生成每日财务快照
- 手动触发快照生成
- 快照查询和对比
- 财务数据校验
- 快照数据导出
- 历史快照管理

### 1.2 技术栈

- 后端：FastAPI + PostgreSQL + SQLAlchemy
- 定时任务：APScheduler
- 数据存储：PostgreSQL
- 缓存：Redis

### 1.3 三层数据模型定位

| 层级 | 数据表 | 说明 |
|------|--------|------|
| 交易事实层 | 各业务交易表 | 快照数据来源 |
| 结构状态层 | `financial_snapshots` | 快照主表 |
| 智能分析层 | `financial_trends` | 趋势分析数据 |

### 1.4 V2.2版本新增功能

| 功能 | 说明 |
|------|------|
| 每日自动快照 | 每日凌晨自动生成前一日的财务快照 |
| 多维度快照 | 包含现金、预收款、库存等多维度数据 |
| 数据校验 | 快照生成时自动校验数据一致性 |
| 快照对比 | 支持不同时间点的快照对比 |
| 趋势分析 | 基于快照数据生成趋势分析 |

```typescript
// src/store/financialStore.ts
import { create } from 'zustand';
import { FinancialSnapshot, FinancialTrend, SnapshotComparison } from '../types/financial';
import { financialApi } from '../services/financialService';

interface FinancialState {
  snapshots: FinancialSnapshot[];
  currentSnapshot: FinancialSnapshot | null;
  trends: FinancialTrend[];
  comparison: SnapshotComparison | null;
  isLoading: boolean;
  error: string | null;
  
  getSnapshots: (startDate: string, endDate: string) => Promise<void>;
  getSnapshot: (date: string) => Promise<void>;
  generateSnapshot: (date: string) => Promise<void>;
  compareSnapshots: (date1: string, date2: string) => Promise<void>;
  getTrends: (periodType: string) => Promise<void>;
  exportSnapshot: (date: string, format: string) => Promise<void>;
  clearError: () => void;
}

const useFinancialStore = create<FinancialState>((set) => ({
  snapshots: [],
  currentSnapshot: null,
  trends: [],
  comparison: null,
  isLoading: false,
  error: null,
  
  getSnapshots: async (startDate, endDate) => {
    set({ isLoading: true, error: null });
    try {
      const snapshots = await financialApi.getSnapshots(startDate, endDate);
      set({ snapshots, isLoading: false });
    } catch (error) {
      set({ error: error instanceof Error ? error.message : '获取快照失败', isLoading: false });
    }
  },
  
  compareSnapshots: async (date1, date2) => {
    set({ isLoading: true, error: null });
    try {
      const comparison = await financialApi.compareSnapshots(date1, date2);
      set({ comparison, isLoading: false });
    } catch (error) {
      set({ error: error instanceof Error ? error.message : '对比快照失败', isLoading: false });
    }
  },
  
  clearError: () => set({ error: null }),
}));

export default useFinancialStore;
```

### 3.2 快照数据来源

| 数据项 | 数据来源 | 计算方式 |
|--------|----------|----------|
| `cash_balance` | `cash_accounts.balance` | 直接查询 |
| `customer_prepaid` | `customer_accounts.balance` | SUM所有客户余额 |
| `inventory_value` | `ingredients` | SUM(库存数量 * 成本单价) |
| `total_assets` | 计算值 | cash_balance + inventory_value |
| `total_liabilities` | 计算值 | customer_prepaid |
| `net_assets` | 计算值 | total_assets - total_liabilities |
| `daily_revenue` | `cash_transactions` | SUM当日收入类型交易 |
| `daily_expense` | `cash_transactions` | SUM当日支出类型交易 |
| `daily_profit` | 计算值 | daily_revenue - daily_expense |
| `order_count` | `orders` | COUNT当日订单 |

## 5. 详细逻辑设计

### 5.1 快照生成流程

```python
async def generate_daily_snapshot(user_id: int, snapshot_date: date) -> FinancialSnapshot:
    """
    生成每日财务快照
    """
    # 1. 检查是否已存在快照
    existing = await db.get_snapshot(user_id, snapshot_date)
    if existing:
        return existing
    
    # 2. 收集数据
    cash_balance = await cash_service.get_balance(user_id)
    customer_prepaid = await customer_service.get_total_prepaid(user_id)
    inventory_value = await inventory_service.get_total_value(user_id)
    
    # 3. 计算汇总数据
    total_assets = cash_balance + inventory_value
    total_liabilities = customer_prepaid
    net_assets = total_assets - total_liabilities
    
    # 4. 获取当日收支
    daily_revenue = await cash_service.get_daily_revenue(user_id, snapshot_date)
    daily_expense = await cash_service.get_daily_expense(user_id, snapshot_date)
    daily_profit = daily_revenue - daily_expense
    
    # 5. 获取订单数
    order_count = await order_service.get_daily_order_count(user_id, snapshot_date)
    
    # 6. 创建快照
    snapshot = FinancialSnapshot(
        user_id=user_id,
        snapshot_date=snapshot_date,
        snapshot_type='daily',
        cash_balance=cash_balance,
        customer_prepaid=customer_prepaid,
        inventory_value=inventory_value,
        total_assets=total_assets,
        total_liabilities=total_liabilities,
        net_assets=net_assets,
        daily_revenue=daily_revenue,
        daily_expense=daily_expense,
        daily_profit=daily_profit,
        order_count=order_count,
        validation_status='pending'
    )
    
    # 7. 保存快照
    await db.save(snapshot)
    
    # 8. 执行数据校验
    validation_result = await validate_snapshot(snapshot)
    snapshot.validation_status = validation_result['status']
    snapshot.validation_errors = validation_result.get('errors')
    
    # 9. 更新校验结果
    await db.update(snapshot)
    
    # 10. 记录事件日志
    await event_log_service.log(
        event_type='financial_snapshot_created',
        entity_type='financial_snapshot',
        entity_id=snapshot.id,
        data={'snapshot_date': str(snapshot_date)}
    )
    
    return snapshot
```

### 5.3 数据校验逻辑

```python
async def validate_snapshot(snapshot: FinancialSnapshot) -> dict:
    """
    校验快照数据一致性
    """
    errors = {}
    
    # 1. 校验资产计算
    calculated_assets = snapshot.cash_balance + snapshot.inventory_value
    if abs(calculated_assets - snapshot.total_assets) > 0.01:
        errors['total_assets'] = f'资产计算不一致: {calculated_assets} != {snapshot.total_assets}'
    
    # 2. 校验净资产
    calculated_net = snapshot.total_assets - snapshot.total_liabilities
    if abs(calculated_net - snapshot.net_assets) > 0.01:
        errors['net_assets'] = f'净资产计算不一致: {calculated_net} != {snapshot.net_assets}'
    
    # 3. 校验利润
    calculated_profit = snapshot.daily_revenue - snapshot.daily_expense
    if abs(calculated_profit - snapshot.daily_profit) > 0.01:
        errors['daily_profit'] = f'利润计算不一致: {calculated_profit} != {snapshot.daily_profit}'
    
    # 4. 校验现金余额（从交易记录重建）
    rebuilt_balance = await cash_service.rebuild_balance(snapshot.user_id, snapshot.snapshot_date)
    if abs(rebuilt_balance - snapshot.cash_balance) > 0.01:
        errors['cash_balance'] = f'现金余额不一致: {rebuilt_balance} != {snapshot.cash_balance}'
    
    return {
        'status': 'validated' if not errors else 'error',
        'errors': errors if errors else None
    }
```

### 5.4 快照对比逻辑

```python
async def compare_snapshots(user_id: int, date1: date, date2: date) -> dict:
    """
    对比两个时间点的财务快照
    """
    snapshot1 = await get_snapshot(user_id, date1)
    snapshot2 = await get_snapshot(user_id, date2)
    
    if not snapshot1 or not snapshot2:
        raise SnapshotNotFoundError('快照不存在')
    
    return {
        'snapshot1': snapshot1,
        'snapshot2': snapshot2,
        'changes': {
            'cash_balance': snapshot2.cash_balance - snapshot1.cash_balance,
            'customer_prepaid': snapshot2.customer_prepaid - snapshot1.customer_prepaid,
            'inventory_value': snapshot2.inventory_value - snapshot1.inventory_value,
            'net_assets': snapshot2.net_assets - snapshot1.net_assets,
            'revenue': snapshot2.daily_revenue - snapshot1.daily_revenue,
            'profit': snapshot2.daily_profit - snapshot1.daily_profit,
        }
    }
```

## 6. 实现注意事项

### 6.1 后端实现注意事项

- 快照生成使用数据库事务保证原子性
- 定时任务需要处理失败重试
- 快照数据不可修改
- 校验失败需要告警通知
- 大量用户时需要分批处理

### 6.2 前端实现注意事项

- 快照列表支持分页加载
- 趋势图表使用合适的可视化组件
- 对比结果清晰展示变化
- 导出功能支持多种格式

### 6.3 性能注意事项

- 快照生成在低峰期执行
- 批量生成时控制并发数
- 历史快照定期归档
- 趋势数据缓存
