# Dot-Store 微信聊天机器人接入方案

## 1. 市场需求分析

### 1.1 目标用户痛点

针对小微实体店铺老板（Dot-Store核心用户）的日常经营痛点：

1. **记录效率低下**：手工记账耗时耗力，容易遗漏或出错
2. **操作门槛高**：需要学习使用专业软件，对技术能力要求较高
3. **信息碎片化**：线下纸质单据、手写记录与线上系统数据分离
4. **即时性需求**：需要随时记录交易，而不是回到电脑前操作
5. **团队协作**：店员需要方便地记录业务数据，无需复杂培训

### 1.2 微信聊天机器人价值

微信作为国内最普及的即时通讯工具，为小微店铺提供了天然的操作入口：

1. **零学习成本**：老板和店员都熟悉微信聊天界面
2. **随时随地操作**：手机拍照即可记录，不受时间地点限制
3. **自然语言交互**：用日常语言描述业务，无需学习专业术语
4. **团队协作便捷**：团队微信群内即可完成数据录入和查询
5. **降低使用门槛**：无需下载安装额外App，提高用户粘性

### 1.3 市场竞争分析

1. **传统ERP/记账软件**：操作复杂，学习成本高，移动化体验差
2. **现有微信小程序**：功能单一，缺乏自然语言交互和OCR能力
3. **其他聊天机器人**：缺乏针对小微店铺的专业业务逻辑

Dot-Store微信机器人的优势在于结合了：
- 微信的普及性和易用性
- 自然语言处理的智能化
- OCR技术的便捷性
- Dot-Store专业的店铺经营管理能力

## 2. 产品功能设计

### 2.1 核心功能概览

| 功能模块 | 具体功能 | 交互方式 |
|---------|---------|---------|
| 自然语言记账 | 记录收入/支出 | 文字描述（如"今天收入500元"） |
|  | 查询报表 | 文字提问（如"本月盈利多少？"） |
|  | 创建订单 | 文字描述（如"新订单：咖啡2杯，18元"） |
| OCR单据识别 | 纸质单据识别 | 拍照上传 |
|  | 手写记录识别 | 拍照上传 |
|  | 异构系统单据识别 | 拍照上传 |
| 业务操作 | 订单状态更新 | 文字指令（如"订单#123已完成"） |
|  | 成本记录 | 文字描述（如"购买原材料1000元"） |
|  | 数据修正 | 文字指令（如"修改订单#123金额为20元"） |
| 系统反馈 | 操作确认 | 机器人回复（如"收入500元已记录"） |
|  | 数据可视化 | 图表或文字摘要 |
|  | 异常提醒 | 机器人主动提示（如"今日未记录任何收入"） |

### 2.2 自然语言交互示例

1. **记录收入**：
   - 用户："今天卖了3杯咖啡，收入54元"
   - 机器人："已记录收入54元，标签：咖啡销售"

2. **查询报表**：
   - 用户："本月总盈利是多少？"
   - 机器人："本月总收入：12,500元，总成本：8,300元，总盈利：4,200元"

3. **创建订单**：
   - 用户："新订单：堂食，2份炒饭，36元"
   - 机器人："已创建订单#1001，金额36元，标签：堂食、炒饭"

4. **数据修正**：
   - 用户："刚才的订单金额错了，应该是42元"
   - 机器人："已将订单#1001金额修改为42元"

### 2.3 OCR单据识别示例

1. **纸质收据识别**：
   - 用户：（上传纸质收据照片）
   - 机器人："识别结果：支出150元，购买原材料。是否确认记录？"
   - 用户："确认"
   - 机器人："已记录支出150元，标签：原材料采购"

2. **手写记录识别**：
   - 用户：（上传手写记账本照片）
   - 机器人："识别结果：收入280元（午餐），支出120元（蔬菜）。是否确认记录？"
   - 用户："确认"
   - 机器人："已记录收入280元（午餐）和支出120元（蔬菜）"

3. **异构系统单据识别**：
   - 用户：（上传外卖平台订单截图）
   - 机器人："识别结果：外卖订单，收入45元，订单号：WD12345。是否确认记录？"
   - 用户："确认"
   - 机器人："已记录外卖订单#WD12345，收入45元"

## 3. 技术架构设计

### 3.1 系统架构图

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  微信聊天界面    │────▶│  微信机器人服务  │────▶│  Dot-Store API  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │                         ▲
                              ▼                         │
                        ┌─────────────────┐     ┌─────────────────┐
                        │  AI服务模块     │◀────│  数据存储层     │
                        │  - NLP处理     │     └─────────────────┘
                        │  - OCR识别     │
                        └─────────────────┘
```

### 3.2 核心组件设计

#### 3.2.1 微信机器人服务

- **技术选型**：企业微信API / 微信公众号API
- **核心功能**：
  - 接收用户消息（文字/图片）
  - 发送机器人回复
  - 身份认证与权限管理
  - 消息日志记录

#### 3.2.2 AI服务模块

- **NLP处理**：
  - 意图识别：判断用户的操作意图（记录收入/支出、查询报表、创建订单等）
  - 实体提取：提取关键信息（金额、标签、订单号等）
  - 自然语言生成：生成友好的机器人回复
  - **技术选型**：可使用开源模型（如ChatGLM）或云服务（如腾讯云NLP）

- **OCR识别**：
  - 文字识别：识别图片中的文字内容
  - 表格识别：识别单据中的表格结构
  - 关键信息提取：提取金额、日期、商品信息等
  - **技术选型**：微信本地OCR API（效果好、速度快、无token费用）或第三方OCR服务

#### 3.2.3 与Dot-Store系统集成

- **API集成**：通过现有Dot-Store API接口进行数据交互
- **数据映射**：将NLP和OCR提取的信息映射到Dot-Store的数据模型
- **事务处理**：确保数据一致性和完整性
- **错误处理**：处理API调用异常和数据验证错误

### 3.3 数据流程设计

1. **自然语言记账流程**：
   - 用户发送文字消息 → 微信机器人服务接收 → NLP意图识别 → 实体提取 → 调用Dot-Store API → 机器人回复确认

2. **OCR单据识别流程**：
   - 用户上传图片 → 微信机器人服务接收 → OCR识别 → 关键信息提取 → 机器人展示识别结果 → 用户确认 → 调用Dot-Store API → 机器人回复确认

3. **报表查询流程**：
   - 用户发送查询请求 → 微信机器人服务接收 → NLP意图识别 → 调用Dot-Store报表API → 机器人展示查询结果

## 4. 核心功能详细设计

### 4.1 自然语言处理能力

#### 4.1.1 意图识别模型

| 意图类型 | 示例用户输入 | 对应API |
|---------|------------|--------|
| 记录收入 | "今天收入500元" | POST /api/ledger/entries |
| 记录支出 | "买原材料花了300元" | POST /api/ledger/entries |
| 创建订单 | "新订单：咖啡2杯，18元" | POST /api/orders |
| 查询今日盈亏 | "今天赚了多少？" | GET /api/reports/summary |
| 查询本月收入 | "本月收入多少？" | GET /api/reports/income |
| 更新订单状态 | "订单#123已完成" | PUT /api/orders/{id} |
| 修改记录 | "修改订单#123金额为20元" | PUT /api/orders/{id} |

#### 4.1.2 实体提取规则

| 实体类型 | 提取规则 | 示例 |
|---------|---------|------|
| 金额 | 数字+元/块/份 | "500元"、"18块"、"2份" |
| 标签 | 商品名称、业务类型 | "咖啡"、"原材料"、"堂食" |
| 订单号 | #+数字 | "#123" |
| 时间 | 今天、本月、昨天 | "今天"、"本月" |

### 4.2 OCR识别能力

#### 4.2.1 支持的单据类型

1. **纸质收据/发票**：识别金额、日期、商品名称
2. **手写记账本**：识别手写数字和文字
3. **外卖平台订单**：识别订单号、金额、商品信息
4. **采购单据**：识别采购物品、数量、金额
5. **异构系统打印单据**：识别系统生成的单据信息

#### 4.2.2 识别精度优化

- **模板匹配**：针对常见单据类型建立识别模板
- **上下文理解**：结合业务场景提高识别准确率
- **人工修正**：允许用户手动修正识别结果
- **持续学习**：基于用户反馈优化识别模型

### 4.3 安全与权限设计

1. **身份认证**：
   - 微信账号绑定Dot-Store店铺账号
   - 团队成员权限管理（如店员只能记录，老板可查询报表）

2. **数据安全**：
   - 消息加密传输
   - 图片数据隐私保护
   - 操作日志记录
   - 符合数据保护法规

## 5. 系统集成与部署

### 5.1 与现有Dot-Store系统的集成

- **API层面**：通过现有Dot-Store API进行数据交互，无需修改核心业务逻辑
- **数据层面**：共享同一数据库，保证数据一致性
- **模块边界**：微信机器人作为独立服务，通过API与Dot-Store系统通信

### 5.2 部署架构

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  微信服务器     │────▶│  微信机器人服务  │────▶│  Dot-Store API  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │                         │
                              ▼                         ▼
                        ┌─────────────────┐     ┌─────────────────┐
                        │  AI服务模块     │     │  数据库         │
                        └─────────────────┘     └─────────────────┘
```

### 5.3 技术栈选择

- **微信机器人服务**：Python + FastAPI
- **NLP处理**：开源模型（如ChatGLM）或云服务（如腾讯云NLP）
- **OCR识别**：微信本地OCR API或第三方OCR服务
- **数据存储**：与Dot-Store共享数据库（PostgreSQL/MySQL）

## 6. 实现路径规划

### 6.1 第一阶段：基础功能实现

1. **微信机器人服务搭建**：
   - 注册企业微信/微信公众号
   - 搭建机器人服务框架
   - 实现消息接收和回复功能

2. **核心NLP功能**：
   - 实现基础意图识别（记录收入/支出、查询今日盈亏）
   - 实现基础实体提取（金额、标签）

3. **与Dot-Store API集成**：
   - 实现收入/支出记录API调用
   - 实现今日盈亏查询API调用

### 6.2 第二阶段：扩展功能实现

1. **高级NLP功能**：
   - 扩展意图识别（创建订单、更新订单状态、修改记录等）
   - 优化实体提取精度

2. **OCR识别功能**：
   - 集成OCR服务
   - 实现图片上传和识别功能
   - 实现关键信息提取和验证

3. **报表查询功能**：
   - 实现本月收入/支出查询
   - 实现订单明细查询

### 6.3 第三阶段：优化与完善

1. **AI模型优化**：
   - 基于用户反馈优化NLP模型
   - 优化OCR识别精度

2. **用户体验优化**：
   - 改进机器人回复的自然度
   - 实现更智能的上下文理解

3. **高级功能**：
   - 实现异常提醒功能
   - 实现数据可视化展示
   - 支持更多复杂业务操作

## 7. 预期效果与评估指标

### 7.1 业务指标

- **用户活跃度**：微信机器人的日活跃用户数
- **操作效率提升**：记账时间减少比例
- **数据完整性**：单据记录的完整性和准确性
- **用户满意度**：用户反馈评分

### 7.2 技术指标

- **响应时间**：机器人平均响应时间（目标：<1秒）
- **NLP准确率**：意图识别准确率（目标：>90%）
- **OCR准确率**：单据识别准确率（目标：>95%）
- **系统可用性**：机器人服务可用性（目标：>99.9%）

## 8. 风险与应对策略

### 8.1 技术风险

- **NLP精度不足**：
  - 应对策略：持续优化模型，提供人工修正入口

- **OCR识别错误**：
  - 应对策略：建立常见单据模板，允许用户手动修正

- **微信API限制**：
  - 应对策略：了解并遵守微信API使用规范，备用方案：微信公众号+小程序组合

### 8.2 业务风险

- **用户接受度**：
  - 应对策略：提供简单易用的操作指南，收集用户反馈持续优化

- **数据安全**：
  - 应对策略：严格遵守数据保护法规，加强数据加密和访问控制

- **团队协作**：
  - 应对策略：提供清晰的权限管理，明确不同角色的操作权限

## 9. 总结与建议

微信聊天机器人接入Dot-Store系统，将为小微实体店铺提供一个零学习成本、随时随地可用的操作入口，显著提升记账效率和用户体验。通过结合自然语言处理和OCR技术，实现了从纸质单据到系统数据的无缝转换，解决了信息碎片化的问题。

建议按照分阶段实施计划推进，先实现基础功能，再逐步扩展和优化，确保系统的稳定性和用户体验。同时，密切关注用户反馈，持续改进AI模型和业务逻辑，以满足小微店铺的实际需求。
