Dot-Store V1 页面原型设计文档
——用于指导 UI / 前端实现 / API 对齐，而不是视觉稿
——文档关联PRD

⸻

0. 设计原则（所有页面必须遵守）

0.1 用户不是“系统使用者”，而是“生意记录者”
	•	不要求用户理解 ERP / 财务 / 流程
	•	不强制完整输入
	•	永远允许「先记下来」

0.2 页面 ≠ 功能模块
	•	页面按用户认知组织
	•	后台模块（Order / Ledger / Event）对用户不可见

0.3 一切围绕「今天」
	•	今天发生了什么
	•	今天赚没赚
	•	今天哪里不对

⸻

1. 页面总体结构（V1）

1.1 一级导航（最多 5 个）

- 今日
- 记录
- 账本
- 报表
- 设置

❗ 不出现：订单管理 / 事件 / 流程 / 财务科目 等专业词

⸻

2. 核心用户操作路径（先于页面）

核心路径 P0（每天必走）

打开系统
 → 查看「今天」
   → 新增一条记录（不完整）
     → 晚些时候补充 / 修正
       → 查看今天盈亏

异常路径 P1（经常发生）

发现账不对
 → 查看账本
   → 找到异常
     → 手工调整
       → 系统留下痕迹

复盘路径 P2（低频但高价值）

打开报表
 → 看一段时间
   → 判断是否调整产品 / 定价 / 活动

3. 页面级原型设计

⸻

3.1「今日」页面（Dashboard / Home）

页面定位

老板每天打开系统的唯一理由

⸻

页面结构

[ 顶部 ]
- 今日日期
- 快速切换日期（昨天 / 明天）

[ 核心信息区 ]
- 今日收入（估算值）
- 今日支出
- 今日盈亏（高亮）

[ 今日发生了什么 ]
- 记录列表（时间倒序）
  - 标签
  - 简要描述
  - 状态（完整 / 待补）

[ 快捷操作 ]
- + 记一笔
- + 调整账目


⸻

核心用户操作

操作 1：快速知道今天赚没赚
	•	不强调精确
	•	允许标注「未完全统计」

操作 2：发现“还没补全的记录”
	•	系统自动提示
	•	不强制处理

⸻

系统行为（供工程理解）
	•	聚合 orders + ledger
	•	允许部分字段为空
	•	显示“估算”状态

⸻

3.2「记录」页面（Record / Orders）

页面定位

把发生的事情记下来

⸻

页面结构

[ 顶部 ]
- + 新记录

[ 筛选 ]
- 按日期
- 按标签
- 按状态（完整 / 待补）

[ 记录列表 ]
- 时间
- 标签（外卖 / 会员 / 活动 / 临时）
- 备注摘要
- 状态标识


⸻

新增记录流程（核心）

Step 1：最小输入

- 时间（默认现在）
- 标签（可选）
- 一句话描述（可选）

👉 此时即可保存

⸻

Step 2：后补信息（可选）

- 金额（可空）
- 关联账目
- 关联会员
- 备注


⸻

设计要点
	•	不出现“订单状态流转”
	•	不要求“完成订单”

⸻

3.3「账本」页面（Ledger）

页面定位

钱是怎么算出来的

⸻

页面结构

[ 顶部 ]
- 当前周期（今天 / 本周 / 自定义）

[ 分类账列表 ]
- 收入类
- 支出类
- 调整类

[ 明细区 ]
- 时间
- 金额（+ / -）
- 来源（自动 / 手工）
- 关联记录（可点）


⸻

核心用户操作

操作 1：发现异常
	•	数字对不上
	•	某类支出异常大

操作 2：手工修正

+ 新增调整
- 金额
- 分类
- 原因（必填）


⸻

设计要点
	•	允许盘盈 / 盘亏
	•	不阻止“脏数据”
	•	必须可追溯

⸻

3.4「报表」页面（Reports）

页面定位

帮助老板做判断，而不是做账

⸻

页面结构

[ 时间选择 ]
- 7 天 / 30 天 / 自定义

[ 核心指标 ]
- 总收入
- 总支出
- 净利润

[ 趋势 ]
- 盈亏变化（简单折线）

[ 分类分析 ]
- 按标签 / 类型


⸻

核心用户操作
	•	判断：
	•	要不要涨价
	•	活动值不值
	•	哪些尝试是失败的

⸻

设计要点
	•	不追求财务报表严谨性
	•	不导出复杂 Excel（V1 不做）

⸻

3.5「设置」页面（Config）

页面定位

让系统像我的店

⸻

页面结构

[ 基础信息 ]
- 店铺名称
- 营业类型（餐饮 / 咖啡 / 其他）

[ 标签管理 ]
- 自定义标签
- 启用 / 停用

[ 显示配置 ]
- 是否显示估算提示
- 是否提示未补全记录


⸻

设计要点
	•	只允许 UI 层配置
	•	不涉及数据结构变更

⸻

4. 页面 → 后台概念映射（关键）

页面	后台核心对象
今日	Order + Ledger 聚合
记录	Order（event 抽象）
账本	Ledger + Audit
报表	Read Model
设置	Config（UI-only）


⸻

5. V1 明确不做的页面

❌ 流程配置
❌ 角色权限
❌ SOP 管理
❌ 自动规则引擎
❌ 高级报表导出


⸻

6. 页面 → API → 数据结构对齐表（V1）

页面	核心 API	主要表	说明
今日	GET /api/summary/today	orders, ledger_entries	聚合视图，只读
今日	GET /api/orders?date=today	orders	显示今日记录
记录	POST /api/orders	orders, events	允许不完整
记录	PUT /api/orders/{id}	orders, audit_logs	任意字段可改
账本	GET /api/ledger/entries	ledger_entries	权威事实
账本	POST /api/ledger/entries	ledger_entries, audit_logs	手工调整
报表	GET /api/reports/summary	ledger_entries	只读聚合
设置	GET/PUT /api/config	（UI-only）	不影响核心数据


⸻

7. 各页面最小字段集（MVP）

今日
	•	date
	•	total_income（估算）
	•	total_expense
	•	net_profit
	•	incomplete_count

⸻

记录（Order）

创建必填
	•	shop_id

可空
	•	amount_estimate
	•	tags
	•	metadata.note

⸻

账本（Ledger Entry）

必填
	•	account_id
	•	amount
	•	direction

强制说明
	•	description（调整原因）

⸻

报表
	•	period_start
	•	period_end
	•	total_income
	•	total_expense
	•	net_profit

⸻

设置（UI）
	•	shop_name
	•	enabled_tags[]
	•	ui_preferences

⸻

使用原则（工程级）
	•	页面字段 ≠ 表字段
	•	所有页面数据必须可由 API 一次返回
	•	禁止页面拼装业务规则
