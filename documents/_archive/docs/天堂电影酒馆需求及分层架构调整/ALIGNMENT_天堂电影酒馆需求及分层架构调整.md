# ALIGNMENT: 天堂电影酒馆需求及分层架构调整

## 项目上下文分析

### 现有项目结构与技术栈
- Dot-Store 是一个面向小微实体店铺的轻量化经营记录与理解工具
- 现有核心模块：Event（事件底座）、Order（订单与交易）、Ledger（分类账与账务）、Report（报表与视图）、Audit（审计与修正）、Config（基础配置）
- 技术栈：Node.js、Prisma、SQLite

### 现有架构模式
- 采用 Event → Order → Ledger → Report 的数据流模型
- 强调记录优先、可解释优先、修正优先的产品原则
- 支持多来源订单和灵活的账务处理

## 需求理解确认

### 原始需求
- 实现天堂电影酒馆的股东体验卡系统
- 支持 Web 端与微信小程序双端访问
- 提供可视化订台、会员周期管理、订单追踪与返现结算等核心功能
- 将现有酒吧系统升级为 Dot-Store 官方发行版 Platform
- 采用 Kernel / Platform / App·Script 三层架构设计

### 边界确认
- **包含范围**：
  - 会员端功能：注册登录、可视化订台、会员周期管理、订单查询、返现积分管理
  - 管理员端功能：座位图管理、预订审批、订单管理、会员管理、返现配置
  - 支付集成：微信支付、支付宝支付
  - 三层架构实现：Kernel、Platform、App/Script 层的功能划分与实现

- **排除范围**：
  - 不包含其他行业的特定功能
  - 不包含复杂的金融结算系统（仅基础返现功能）
  - 不包含企业级权限管理系统

### 需求理解
- 本需求是对现有 Dot-Store 架构的扩展和重构
- 将单一行业系统升级为可扩展的三层架构平台
- 核心是建立清晰的分层职责边界，确保 Kernel 层的稳定性和 Platform 层的行业适配性
- App/Script 层提供门店定制能力，避免代码硬编码

## 智能决策策略

基于现有项目内容和行业知识，我们可以做出以下决策：

1. **架构设计**：
   - 采用 Event-first 的资源占用模型，确保高并发下的系统稳定性
   - Kernel 层保持无行业语义，仅提供原子能力
   - Platform 层实现餐饮/酒吧行业的具体业务逻辑
   - App/Script 层提供门店定制能力

2. **数据模型**：
   - Resource 模型作为抽象资源，Table/Booth 作为具体行业资源
   - ResourceEvent 记录资源占用事件
   - Account + Ledger 模型实现通用的账户和数值管理

3. **实现路径**：
   - 阶段1：抽离 Kernel 层，实现基础原子能力
   - 阶段2：重建 Platform 层，实现行业业务逻辑
   - 阶段3：实现 App/Script 层，提供定制化能力

## 结论

本需求将 Dot-Store 从单一行业系统升级为可扩展的三层架构平台，核心是建立清晰的分层职责边界。通过本次调整，系统将具备更好的可扩展性和灵活性，能够支持更多行业和定制化需求。
