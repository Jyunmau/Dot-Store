## 测试执行流程

### 1. 测试环境准备

#### 1.1 后端环境

```bash
# 安装依赖
cd backend
pip install -r requirements.txt

# 配置测试数据库
# 在 config/database.py 中设置测试数据库连接

# 运行数据库迁移
alembic upgrade head
```

#### 1.2 前端环境

```bash
cd frontend
npm install
```

#### 1.3 测试数据初始化

```bash
# 运行测试数据准备脚本
python scripts/init_test_data.py
```

### 2. 测试执行

#### 2.1 单元测试执行

```bash
# 运行所有单元测试
pytest tests/unit/ -v

# 运行特定模块单元测试
pytest tests/unit/test_order.py -v
```

#### 2.2 集成测试执行

```bash
# 运行所有集成测试
pytest tests/integration/ -v

# 运行端到端测试
pytest tests/e2e/ -v
```

#### 2.3 测试报告生成

```bash
# 生成HTML测试报告
pytest --html=report.html --self-contained-html

# 生成覆盖率报告
pytest --cov=app --cov-report=html
```

### 3. 测试优先级

| 优先级 | 用例类型 | 执行顺序 | 说明 |
|--------|---------|---------|------|
| P0 | 核心业务功能测试 | 第一轮 | 用户认证、订单、支付等核心流程 |
| P1 | 重要功能测试 | 第二轮 | 客户账户、库存、现金流分析等 |
| P2 | 边界/性能测试 | 第三轮 | 边界值、性能、安全测试 |

## 常见问题解决方法

### 4.1 测试数据问题

**问题**：测试数据准备失败
**解决方法**：
1. 检查数据库连接配置
2. 确认数据库用户权限
3. 查看错误日志具体信息

**问题**：测试数据被污染
**解决方法**：
1. 每个测试用例使用独立的事务
2. 测试结束后回滚事务
3. 定期清理测试数据

### 4.2 环境配置问题

**问题**：依赖安装失败
**解决方法**：
1. 检查Python版本
2. 清理pip缓存：`pip cache purge`
3. 使用国内镜像源

**问题**：数据库连接失败
**解决方法**：
1. 检查数据库服务是否启动
2. 确认数据库配置正确
3. 检查防火墙设置

### 4.3 测试执行问题

**问题**：测试用例超时
**解决方法**：
1. 增加超时时间配置
2. 检查数据库查询性能
3. 优化测试数据量

**问题**：测试用例不稳定
**解决方法**：
1. 检查测试用例是否有依赖关系
2. 添加适当的等待时间
3. 使用固定测试数据

### 4.4 报告生成问题

**问题**：覆盖率报告为空
**解决方法**：
1. 确认已安装coverage插件
2. 检查__init__.py文件是否存在
3. 确认代码路径配置正确

## 维护规范

### 5.1 文档更新

- 所有测试文档的更新遵循项目根目录的文档更新机制
- 新增或修改测试用例时，请确保更新本目录索引
- 测试文档版本管理通过Git进行，确保所有变更都有记录

### 5.2 测试用例管理

- 测试用例ID统一编号规则：UT_模块_序号 / IT_模块_序号 / IT_E2E_序号
- 测试用例命名规范：用例名称需清晰表达测试目的
- 测试用例优先级：P0为核心功能，P1为重要功能，P2为次要功能

### 5.3 测试数据管理

- 测试数据使用测试数据库，不使用生产数据
- 敏感测试数据需脱敏处理
- 测试数据需定期清理和重建

### 5.4 缺陷管理

- 发现缺陷需创建Issue，标题前缀【缺陷】
- 缺陷需标注优先级和复现步骤
- 修复后需执行回归测试
